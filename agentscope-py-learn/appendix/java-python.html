先换脑子：Reactor vs asyncio

Java 2.0.4 Python 2.0.11 注意
Mono<T>Awaitable[T] / 协程一个结果
Flux<T>AsyncGenerator[T, None]多个结果 / 事件流
.block()await ...同步等待；不要在事件循环里阻塞
取消订阅取消 task / aclose()生成器关闭要释放资源
背压消费速度 / 有界队列Python 异步生成器没有自动背压
不要机械翻译链式调用

Java 的 flatMap / concatMap 在 Python 里通常变成 async for 或 asyncio.gather； 先想清楚顺序、并发与取消，再写代码。

服务形态

这是两套实现差异最大的地方：

维度 Java 2.0.4 Python 2.0.11
服务入口agentscope-service 的 Java Gateway + Dataplane，加 Go 写的 Control（aistiod）create_app 的 FastAPI
资源模型Service 的 Agent / Session / Run / AttemptAgent / Session / Workspace / Schedule / Credential
鉴权Gateway 只做路径路由，不鉴权；JWT / 内部令牌由目标组件校验get_current_user_id 依赖可覆盖
协议Endpoint / SSE / 控制面REST + SSE + 可选 AG-UI；A2A 是客户端适配器，服务端需自建
部署Compose / K8s / PostgreSQLDocker / uvicorn / Redis 或 SQL
扩展运行时 + 网关分层扩展extra_middlewares / extra_agent_* / 自定义依赖
Python 的 create_app 不是 Java Service 的端口

Java 的 Service 是独立控制面 + 网关；Python 的 create_app 把 API、会话、存储、SSE 放在一个进程里。先跑通单体，再按需要拆 worker。

迁移清单

  1. 先统一术语：ToolUse → ToolCall，RuntimeContext → AgentState / 会话
  2. 再换异步模型：Mono / Flux → await / async for，取消与关闭要显式处理
  3. 再换 Agent：HarnessAgent builder → Agent 构造 + create_app
  4. 再换工具：@Tool → FunctionTool，权限用 PermissionDecision
  5. 再换服务：不要照搬 Java Service 的 Gateway / Dataplane / Control 拆分；先用 create_app 单体
  6. 最后换运维：PostgreSQL → Redis / SQL，重做迁移、备份、健康检查
检查项 标准
Agent 调用没有 agent(...)；只有 reply / reply_stream
工具 schema由 Python 签名 / docstring 生成，描述清楚
状态会话可恢复；多副本共享存储
服务鉴权已替换；下载密钥共享；调度 / 渠道单例
观测TracingMiddleware 接 OTLP；token 可统计
测试假模型单测 + 真实模型夜间冒烟
