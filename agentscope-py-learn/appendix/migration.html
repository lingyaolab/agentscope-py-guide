D · 版本迁移

AgentScope 2.0 是破坏性更新，不是改几个 import 就能升级。 这一页按模块列出变化，并给出一条可执行的迁移顺序。

2.0 是一次破坏性更新

官方 change-log 的定位很明确：Agent、消息、工具、模型、状态、服务都重写过。 迁移时不要「边跑边修」，先列清单，再逐层替换。

模块 1.x 2.0
AgentReActAgent + __call__Agent + reply / reply_stream
扩展点hook 机制中间件系统
状态state_dict / load_state_dictAgentState
追踪Agent 内部 OTelTracingMiddleware
消息Image / Audio / Video 块统一 DataBlock
工具各自注册ToolBase + Toolkit
模型凭证与模型耦合Credential 分离 + ModelCard
服务无内建服务app.create_app（FastAPI）
记忆memory 模块移除，改为 RAG / 长期记忆中间件

Agent：从 __call__ 到 reply_stream

1.x 通过 agent(...) 触发；2.0 改成两个公共方法：

方法 返回 用途
reply_stream(...)_agent.py:289异步事件流前端实时渲染、可观测、HITL
reply(...)_agent.py:333Msg只要最终答案
 
from agentscope.agent import Agent
from agentscope.message import UserMsg


async def ask(agent: Agent) -> str | None:
    msg = await agent.reply(
        UserMsg(name="user", content="你好"),
    )
    return msg.get_text_content()

同时被移除或替换的：state_dict / load_state_dict、 Agent 的 print 接口、Agent 内部 OTel。状态改由 AgentState 显式管理，追踪交给中间件。

不要再用 hook 思维

旧 hook 的「前后切一刀」在 2.0 由 MiddlewareBase 承担。 但中间件是洋葱模型，能改事件流、能拦工具，不只是日志。

Message：内容块重组

1.x 2.0 迁移动作
ImageBlock / AudioBlock / VideoBlock DataBlock + media_type 按媒体类型构造 DataBlock，不要找旧类名
ToolUseBlock ToolCallBlock 全局替换类名；新增 state 与 suggested_rules
普通文本块 TextBlock 内容校验更严格
无 hint 块 HintBlock 运行时引导改用 HintBlock
无统一 id 所有 block 带 id 事件与消息可以稳定关联

Msg 也重写了：Pydantic 校验、created_at / finished_at / usage、append_event， 以及 UserMsg / AssistantMsg / SystemMsg 工厂。 

from agentscope.message import TextBlock, UserMsg

msg = UserMsg(
    name="user",
    content=[TextBlock(text="你好")],
)
print(msg.get_text_content())

工具：ToolBase 与 Toolkit

2.0 把工具、技能、MCP、工具组统一进 Toolkit：

  • ToolBase 是所有工具的基类
  • FunctionTool 把普通函数变成工具
  • MCPTool 包装 MCP 工具
  • ToolGroup 支持按需激活，basic 组常驻
  • ResetTools 是运行时切换工具组的元工具
from agentscope.tool import FunctionTool, Toolkit


def get_weather(city: str) -> str:
    """查询城市天气。"""
    return f"{city}: sunny"


toolkit = Toolkit(tools=[FunctionTool(get_weather)])

旧代码里「自己维护工具 schema」的部分可以删掉：签名、类型、docstring 现在直接生成 schema。但这也意味着 docstring 的质量直接影响模型行为。

模型：credential 与 formatter 分离

变化 影响
凭证从模型类解耦一个凭证可被多个模型 / 会话复用；服务层可做共享
formatter 集成进 chat model每种 provider 有默认 formatter；假模型也要设置
新增 ModelCard 与 list_models()前端可发现模型能力与参数 schema
新增 Kimi / Moonshot / DeepSeek / XAI / OpenAI Response迁移时按 provider 选类，不要再用旧 wrapper
废弃 Trinity wrapper多模型路由改用 ModelRouterMiddleware 或 fallback

迁移时先把「key 从代码里拿出来」，放进 CredentialBase 子类； 再把模型的 formatter 交给默认实现，不要手工拼 provider 请求。

新增 Agent Service

1.x 没有内建 HTTP 服务。2.0 新增 app 模块：

组件 作用
create_appFastAPI 工厂，统一暴露 agent / chat / session / schedule / workspace 等路由
StorageBaseRedis 或 SQLAlchemy 持久化
MessageBus会话锁、回放、收件箱、唤醒
WorkspaceManager多租户工作区生命周期
ChatRunRegistry同一会话只允许一个在途 run

迁移顺序是「先让 SDK 跑通，再上服务」。不要一上来就把旧业务塞进 create_app，否则分不清是 SDK 还是服务层的问题。

memory 模块移除

2.0 废弃了 1.x 的 memory 模块，原因是它与 Agent 逻辑耦合过深。 替代方案：

  • 短期上下文：AgentState.context + ContextConfig
  • 长期记忆：AgenticMemoryMiddleware、Mem0Middleware、ReMeMiddleware
  • 可检索事实：知识库 + RAGMiddleware
  • 超大内容：Offloader + 工作区
别把 memory 直接映射成知识库

记忆是「跨会话的用户事实」，知识库是「可检索的共享文档」。 混在一起会导致上下文膨胀、共享边界混乱。

迁移顺序

  1. 锁版本：先固定 agentscope==2.0.11，建一个分支
  2. 换依赖：模型扩展、可选 extras（a2a / realtime / sql / vdb）按需安装
  3. 换消息：ToolUse → ToolCall，Image/Audio/Video → DataBlock，补 block id
  4. 换 Agent：__call__ → reply / reply_stream，状态改 AgentState
  5. 换工具：注册到 Toolkit，用 ToolBase / FunctionTool
  6. 换模型：拆 credential，设置 formatter，补 ModelCard
  7. 换扩展：hook → 中间件，内部 OTel → TracingMiddleware
  8. 上服务：最后才接 create_app，先单进程再水平扩展
  9. 补测试：假模型 + 事件断言 + 黄金样本，再跑真实模型冒烟

迁移检查清单

检查项 通过标准
Agent 调用不再出现 agent(...)；只有 reply / reply_stream
状态不再用 state_dict；状态可序列化 / 恢复
消息块没有 ToolUseBlock / ImageBlock 等旧类名
工具 schema由 ToolBase / FunctionTool 生成，且有 docstring
凭证key 不在代码与镜像里；可被多个模型复用
追踪使用 TracingMiddleware，不再依赖 Agent 内部 OTel
记忆不再 import agentscope.memory
服务单进程能跑通，再多副本；scheduler / channel 单例
测试假模型测试不访问网络；真实模型只跑夜间 / 发布前
