G · 动手练习答案

这不是标准答案，而是「参考实现 + 检查点」。同一道练习可以有不同的写法， 重点是你能不能解释每一步为什么这样做。建议先自己写，再对照。

怎么用这份答案

  • 先跑通自己的版本，再对照参考实现，不要直接抄。
  • 重点看「检查点」：它们比代码更能说明你有没有理解。
  • 如果代码能跑但检查点答不上来，回到对应章节重读。

第 01–03 章：环境、第一个 Agent 与消息事件

01 的改语言实验不需要动其他代码，只改系统提示；02 的流式实验直接复用 reply_stream 的事件循环。 

from agentscope.event import EventType
from agentscope.message import UserMsg


async def stream_once(agent) -> None:
    async for event in agent.reply_stream(
        UserMsg(name="user", content="用三句话解释 ReAct。"),
    ):
        if event.type == EventType.TEXT_BLOCK_DELTA:
            print(event.delta, end="", flush=True)
        elif event.type == EventType.REPLY_END:
            print(f"\n[done] {event.finished_reason}")

检查点：

  • 改 system_prompt="Only answer in English." 后，如果仍是中文，先确认没有第二处系统提示覆盖它。
  • 首字延迟看第一个 TEXT_BLOCK_DELTA，不是整个流结束时间。
  • 换 OllamaChatModel 只改模型构造；Agent、UserMsg、Toolkit 的代码不动，能跑通说明模型层是解耦的。
  • ReActConfig(max_iters=1) 遇到需要两次工具调用的问题时，应以 exceed_max_iters 结束，而不是假装成功。
  • 事件 reducer 只处理 TEXT_BLOCK_START / TEXT_BLOCK_DELTA / REPLY_END 就够了；先别把所有事件类型都塞进状态机。
  • msg.model_dump(mode="json") 再 Msg.model_validate 后，内容块的数量与类型应完全一致。

第 04–05 章：模型接入与工具系统

模型练习的重点是「看清边界」：哪些是凭证错误，哪些是模型能力， 哪些是框架的重试策略。 

from agentscope.message import TextBlock
from agentscope.permission import (
    PermissionBehavior,
    PermissionContext,
    PermissionDecision,
)
from agentscope.tool import ParamsBase, ToolBase, ToolChunk


class CityParams(ParamsBase):
    city: str


class CityWeatherTool(ToolBase):
    name = "get_weather"
    description = "查询指定城市的天气，只读。"
    input_schema = CityParams.model_json_schema()
    is_read_only = True

    async def check_permissions(
        self,
        tool_input: dict,
        context: PermissionContext,
    ) -> PermissionDecision:
        if tool_input.get("city") not in {"Beijing", "Shanghai"}:
            return PermissionDecision(
                behavior=PermissionBehavior.DENY,
                message="only two cities are allowed",
            )
        return PermissionDecision(
            behavior=PermissionBehavior.ALLOW,
            message="read-only weather query",
        )

    async def call(self, city: str) -> ToolChunk:
        return ToolChunk(content=[TextBlock(text=f"{city}: 18C, sunny")])

检查点：

  • DeepSeekCredential.list_models() 返回的是卡片列表；标了 sunset 的模型即使还能调，也不该放进新项目。
  • stream=True 时最后一项 is_last=True 才带完整 usage；只读第一项会得到 0。
  • key 写错会第一次就抛 AuthenticationError，不会重试四次；重试只针对可重试错误。
  • ToolGroup 里的工具默认不激活；模型先调用 reset_tools 才会看到它们。
  • 工具抛异常时，框架把可读错误文本回给模型，整轮对话不中断；这和自己把异常吞掉是两回事。

第 06–08 章：上下文、中间件与权限

中间件的最小实验是「只观察，不改变」：先打印模型调用的输入规模， 确认插入点正确，再加逻辑。 

from agentscope.middleware import MiddlewareBase


class ModelAuditMiddleware(MiddlewareBase):
    async def on_model_call(self, agent, input_kwargs, next_handler):
        messages = input_kwargs.get("messages", [])
        print(
            f"[model] agent={agent.name} "
            f"messages={len(messages)} model={type(agent.model).__name__}",
        )
        return await next_handler(**input_kwargs)

检查点：

  • tool_result_limit=200 后，长输出应出现截断标记；模型后续行为会受截断影响，这是预期。
  • 挂上 LocalWorkspace 后，截断的完整结果落在 sessions/{id}/tool_result-*.txt。
  • timezone="Asia/Shanghai" 与更小的时间间隔，会影响 HintBlockEvent 里的时间文本。
  • on_system_prompt 是按列表顺序接力的；后一个中间件看到的是前一个改过的提示。
  • PermissionMode.EXPLORE 下写文件应被直接拒绝，不进入确认流程。
  • 最小确认循环：捕获 RequireUserConfirmEvent，第一次拒绝、第二次确认，比较两轮回复。

第 09–11 章：流水线、计划 SOP 与 RAG

流水线练习先写「验证者怎么判 fail」，再写执行者。验证标准不清楚， max_iters 调多大都没用。 

from agentscope.pipeline import GoalPipeline

pipe = GoalPipeline(
    executor=executor,
    verifier=verifier,
    max_iters=1,
)
# 第一次验证 fail 后，max_iters=1 应立即停止，而不是无限重试

检查点：

  • GoalPipeline 的停止条件是「验证通过」或「达到 max_iters」；只设退出条件不设上限可能一直跑。
  • TeamPipeline 的事件流里，reply_id 会在队长与成员之间切换；跟着它看是谁在说话。
  • 任务工具不会替模型检查依赖顺序；被阻塞的任务仍可能被先做，这是设计边界，不是 bug。
  • SOP 第一步带验证者、第二步不带时，事件流里应只有第一步出现验证相关事件。
  • TextParser + ApproxTokenChunker 切块后，chunk_index 与 total_chunks 应能对上。
  • QdrantStore(location=":memory:") 适合练习；生产要换成持久化地址。
  • static 模式不会出现 search_knowledge 工具调用；agentic 模式会出现。
  • 长期记忆跟着 workdir 走；新建 Agent 复用同一个 workdir 才能看到之前的偏好。

第 12–14 章：工作区、中断恢复与控制台

工作区练习要同时看「文件落在哪」和「工具在哪执行」。 这两件事在 Local 与 Docker 下不一样。 

from agentscope.workspace import LocalWorkspace

async with LocalWorkspace(workdir="./workspace") as ws:
    tools = await ws.list_tools()
    # 让 Agent 写文件，再去 ws.workdir 里读回来

检查点：

  • LocalWorkspace 的文件落在 workdir；DockerWorkspace 的路径在容器里，不是宿主机的同一个路径。
  • 直接构造 Bash 不传 backend 时，执行位置与 workspace.list_tools() 里的 Bash 不同。
  • async with 退出后，容器或临时目录应被清理；没清理先看是否有异常跳过了上下文管理器。
  • 状态存成 JSON 再恢复时，工具调用与结果要成对出现；恢复后继续问相关问题，模型应记得上一轮。
  • task.cancel() 后，每个 tool_call 都应有对应的 tool_result，哪怕是中断结果。
  • HITL 挂起时发 UserInterruptEvent，事件流里应出现中断结果，而不是继续等待确认。
  • launch_console 的 y 是确认、a 是总是允许；两者对后续工具调用的影响不同。
  • verbosity="debug" 才能看到模型调用开始/结束与 token 用量。

第 15–18 章：Agent Service、SSE、团队与渠道

服务练习先跑最小闭环，再谈多副本。单进程用 SQLite + 进程内总线， 多副本再换 Redis。 

from agentscope.app import create_app
from agentscope.app.message_bus import InMemoryMessageBus
from agentscope.app.storage import AsyncSQLAlchemyStorage
from agentscope.app.workspace_manager import LocalWorkspaceManager

app = create_app(
    storage=AsyncSQLAlchemyStorage("sqlite+aiosqlite:///./as.db"),
    message_bus=InMemoryMessageBus(),
    workspace_manager=LocalWorkspaceManager(basedir="./workspaces"),
)

检查点：

  • /docs 能看到 OpenAPI；/health 也要带 X-User-ID，否则 422。
  • 建 Agent → 建凭证 → 建会话 → POST /chat → 订阅 SSE，顺序不能反；没有凭证时创建会话会失败。
  • 流式中途 POST /sessions/{id}/interrupt 后，会话应回到可继续状态，而不是永久 running。
  • 覆盖 get_current_user_id 后，后续请求不再需要 X-User-ID；这只是依赖覆盖，不是鉴权方案。
  • curl -N 订阅后再发 POST /chat，先收到回放、再收到实时事件。
  • 断线重连带 after=event_cursor，不应丢帧；before 是翻页，不是重放游标。
  • /status 的 awaiting_permission 表示工具在等确认，不是错误。
  • 团队不需要 team=true；Leader 会话自动拿到团队工具，Worker 只有 TeamSay。
  • per_chat_user 下，同一群聊里两个用户各自一个会话；per_chat 则整群共享。
  • 自定义渠道先只打印 ChannelEvent 再回固定文本，确认路由通了再接平台 SDK。

第 19–21 章：中心、共享与观测

共享策略先写「谁能看到谁」，再写「能不能改」。两个方法分开， 才不会把只读共享误做成可编辑。 

from agentscope.app.access import (
    ResourceAccessPolicyBase,
    ResourceKind,
    ResourceRef,
    ResourcePermission,
)


class DictPolicy(ResourceAccessPolicyBase):
    async def list_accessible(self, viewer_id, kind, storage):
        if viewer_id == "bob" and kind == ResourceKind.CREDENTIAL:
            return [
                ResourceRef(
                    kind=kind,
                    owner_id="alice",
                    resource_id="cred-openai",
                    permission=ResourcePermission.READ,
                ),
            ]
        return []

检查点：

  • 安装 ≠ 装配：MCP/技能装进资源池后，还要在工作区里装配给某个 Agent。
  • 只对特定用户可见的 Hub，要在 list_* 与 get_* 两处都过滤；只过滤列表仍可通过 id 直接取。
  • 卡片加 api_key 输入时，前端应渲染成密码框；这是 UI 约定，不是加密。
  • Bob 列出 Alice 共享的凭证时能看到名字与类型，但看不到 key；原始密钥只在运行时解析。
  • READ → EDIT 后，editable 与 PATCH/DELETE 行为一起变；只改一个地方会出现「按钮能点但接口 403」。
  • 共享 Agent 不共享工作区、MCP、技能与记忆；Bob 从干净 workspace 开始。
  • 用 ConsoleSpanExporter 数 span 树节点，先确认一次 reply 的父子关系，再接 OTLP。
  • token 中间件在 ReplyEndEvent 汇总 input/output；usage 缺失时要有 0 或未知的降级值。
  • 预算中间件要能阻止下一轮工具调用，而不是只打日志；用小预算触发一次验证。
  • 带图片的消息 span 属性可能很大；在 Collector 侧裁剪，不要指望模型侧自动瘦身。

第 22–23 章：评测与生产化

评测先保证「不访问网络」，再谈指标。假模型能跑通， 说明你的断言在看行为，不是在碰运气。 

# 检索指标的最小实现
def recall_at_k(retrieved, relevant, k=3):
    hit = len(set(retrieved[:k]) & set(relevant))
    return hit / len(relevant) if relevant else 0.0


def mrr(retrieved, relevant):
    for rank, doc_id in enumerate(retrieved, start=1):
        if doc_id in relevant:
            return 1.0 / rank
    return 0.0

检查点：

  • ScriptedChatModel 不应访问网络；测试里出现真实 key 或 DNS 请求，说明替身没接上。
  • 模型调用不存在的工具时，ToolResultEndEvent.state == "error"，不是整轮抛异常。
  • behavior_signature 改坏工具名后，报错信息应能定位到具体用例。
  • 小知识库标 5 个问题，先算 recall@3 与 MRR，再看生成指标；检索没命中时不要调提示词。
  • CI 分 unit 与 live 两个 job；PR 只跑 unit，live 用夜间或手动触发。
  • 模型超时设 10 秒，用慢接口验证 APITimeoutError 路径，而不是只改配置不验证。
  • SDK 重试与 AgentScope 重试叠在一起会放大请求次数；数日志里的实际请求，不要数配置项。
  • 并发限制中间件用信号量时，流结束、异常、取消三条路径都要释放。
  • 两个 uvicorn worker 共享 Redis 时，同一会话重复提交应得到 409；单进程的 409 与跨进程的等待语义不同。
  • /health 带身份头用于就绪检查，/livez 不依赖身份用于存活检查。

第 24–26 章：A2A、语音与综合案例

A2A 练习先跑通「同一 context_id 的第二轮」， 再谈 Task 生命周期与推送；语音练习先跑通本地声卡，再换浏览器传输。 

# 续接同一段远端会话
stored = A2AAgentState(
    context_id="ctx-123",
    task_id=None,
)
agent = A2AAgent(card, state=stored)

# 服务端停在 INPUT_REQUIRED 时，task_id 仍保留；
# 下一轮用同一个 task_id 继续，而不是新建任务

检查点：

  • A2A 流式 artifact 的顺序应与服务端 Task 状态变化一致；只看到最终文本说明中间状态被吞了。
  • context_id 管「同一段对话」，task_id 管「这一次任务」；两者不要混用。
  • INPUT_REQUIRED 不是失败，是远端在等输入；本地不要把它当异常结束。
  • DataBlock 图片会转成 URL 或 raw Part；超出支持范围的内容要提前拒绝。
  • A2A 调用加自定义 span，把 context_id 与 task_id 写进属性，跨组织排障才定位得到。
  • TTS 合成看 is_last 行为；只保存第一个音频块会得到半句话。
  • TTSMiddleware 给文本 Agent 配音时，音频事件与文本事件是两条流，不要假设一一对应。
  • ASR 的 language 与 prompt 会显著影响转写；先用一段固定录音做基线。
  • RealtimeAgent 打断后，last_turn_metrics 应能说明本轮延迟；打断不会自动裁剪上下文。
  • 自定义传输要模拟浏览器上报的播放位置，否则服务端不知道用户听到哪。
  • 综合案例先跑最小闭环，再按凭证 → Agent → 会话 → 知识库 → 共享 → 追踪 → 评测逐层加。
  • 上线前 /health 所有组件 ok；3 条假模型回归 + 1 条真实模型冒烟接进 CI。
