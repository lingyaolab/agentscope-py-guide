01 · 环境与依赖

这一章只做一件事：让你在 25 分钟内看到一个由 AgentScope 2.0.11 驱动的 Agent 真的回话。 同时把「装了什么、为什么装、装错会怎样」讲清楚，后面所有章节都建立在这套环境上。

读完你能做到

  • 用 uv 或 pip 建一个 Python 3.11+ 虚拟环境，并装上 agentscope==2.0.11
  • 用 DeepSeekCredential + DeepSeekChatModel 组装一个最小 Agent，跑通一次 reply()
  • 说清 Agent、ChatModel、Toolkit、Msg 各自负责什么，以及一次 ReAct 的循环边界

先说为什么：Agent 不是「一个会说话的模型」

一个只会 chat.completions.create() 的脚本，输入一段文本、输出一段文本，仅此而已。 Agent 多出来的是循环：模型可以决定「先调用一个工具」，拿到结果后继续推理，直到它认为可以给出最终回答。 这个「推理 → 行动 → 再推理」的循环，就是 ReAct。

模型（ChatModel）
只负责一次「给定上下文，产出下一段内容或工具调用请求」。它不执行工具，也不记得上一轮。
工具（Toolkit）
把 Python 函数、MCP 服务、技能注册成模型能看懂的 schema；真正执行的是你的代码。
智能体（Agent）
持有系统提示、工具集与状态，驱动 ReAct 循环、检查权限、处理中断，最后产出一条 Msg。

AgentScope 2.0 的 Agent 被设计成无状态的推理-行动引擎：对话历史放在 AgentState 里，Agent 本身只负责「这一轮怎么走」。默认情况下它会自己创建一份状态 _agent.py:175， 所以最小示例不需要你手动管理。

3. main.py

import asyncio
import os

from agentscope.agent import Agent
from agentscope.credential import DeepSeekCredential
from agentscope.message import UserMsg
from agentscope.model import DeepSeekChatModel
from agentscope.tool import Toolkit


async def main() -> None:
    agent = Agent(
        name="Friday",
        system_prompt="You are a helpful assistant named Friday.",
        model=DeepSeekChatModel(
            credential=DeepSeekCredential(
                api_key=os.environ["DEEPSEEK_API_KEY"],
            ),
            model="deepseek-chat",
        ),
        toolkit=Toolkit(),
    )

    msg = await agent.reply(
        UserMsg(name="user", content="用三句话解释什么是 ReAct。"),
    )

    for block in msg.content:
        if block.type == "text":
            print(block.text)


if __name__ == "__main__":
    asyncio.run(main())

运行：

python main.py

如果看到一段中文回答，环境就通了。注意 Toolkit() 是空的：这一轮不会发生工具调用， 但仍然走完整的 ReAct 循环，只是第一次模型调用就直接给出了最终回答。

逐行解读：容易懵的地方

Agent 的构造参数

Agent 的构造函数 _agent.py:121 只有 name、system_prompt、model 是必填，其余都有默认值。 最常改的是这四个：

参数 作用 不传时
toolkit 工具、MCP、技能的唯一起点 内部创建一个空 Toolkit()_agent.py:202
state 对话历史与运行状态 新建一份 AgentState()_agent.py:175
middlewares 在 reply / 推理 / 工具等钩子上扩展行为 空列表
react_config 循环上限、结构化输出宽限、拒绝后是否停止 ReActConfig()，最多 50 轮_config.py:367

模型的两个默认值

DeepSeekChatModel 的构造函数 _model.py:79 里有两个容易忽略的默认：

  • stream=True_model.py:84：底层默认走流式；reply() 会在内部把流式结果聚合成完整消息。
  • max_retries=3、retry_delay=1.0_model.py:85：网络抖动时自动重试，不是你业务层的重试。
  • context_size=65536_model.py:87：用于上下文压缩的预算基准，不是模型的硬上限。

消息为什么是「内容块列表」

Msg.content 的类型是 list[ContentBlock] _base.py:80， 而不是一个字符串。因为一条消息里可能同时有文本、思考、工具调用、工具结果、图片或音频。 UserMsg(...) 是便捷构造器 _base.py:569， 传字符串时会自动包成 TextBlock。

reply 与 reply_stream 的区别

reply() _agent.py:333 把事件流消费完，只返回最后一条 Msg； reply_stream() _agent.py:289 则把中间事件逐个交给你，适合做打字机效果和工具调用可视化。 

from agentscope.event import EventType

async for event in agent.reply_stream(user_msg):
    if event.type == EventType.TEXT_BLOCK_DELTA:
        print(event.delta, end="", flush=True)
    elif event.type == EventType.TOOL_CALL_START:
        print(f"\n[calling tool] {event.tool_name}")

事件类型的完整列表在 _event.py:25， 文本增量是 TEXT_BLOCK_DELTA _event.py:35， 工具调用开始是 TOOL_CALL_START _event.py:48。

端到端：一条消息怎么走完一次 ReAct

把 await agent.reply(...) 拆开，大概是这样一条时间线：

1. 组装输入
把你的 UserMsg 追加进状态，连同系统提示、历史消息、工具 schema 一起准备成模型输入。
2. 调用模型（reasoning）
_call_model _agent.py:3291 把输入发给 DeepSeekChatModel，流式拿回文本增量或工具调用。
3. 有工具调用就执行（acting）
_acting_impl _agent.py:2785 先过权限检查，再执行工具，把结果写成 ToolResultBlock 追加回上下文。
4. 回到第 2 步，直到没有工具调用
循环由 _reply_impl _agent.py:1036 控制；超过 max_iters=50 会以 EXCEED_MAX_ITERS 结束。
5. 产出最终消息
reply 从事件流里取出最后一条 Msg 返回。
为什么「空 Toolkit」也能跑

模型的输出可以是「直接回答」，也可以是「请求调用工具」。当工具集为空时，模型没有可调用的工具， 通常会直接回答。所以最小示例不需要任何工具，但循环本身是完整存在的。

核心包只包含 SDK 必需项；服务、RAG、向量库、沙箱、渠道等都是独立的 extra pyproject.toml:54。 常见组合：

你要做什么 安装 主要 extra

模型接入：DeepSeek / OpenAI 兼容 / 本地 Ollama

AgentScope 把「凭证」和「模型」拆成两个对象：Credential 负责 API Key 与 base URL， ChatModel 负责调用与解析。换厂商就是换一对类。

DeepSeek（本站默认）

from agentscope.credential import DeepSeekCredential
from agentscope.model import DeepSeekChatModel

model = DeepSeekChatModel(
    credential=DeepSeekCredential(
        api_key=os.environ["DEEPSEEK_API_KEY"],
    ),
    model="deepseek-chat",
)

DeepSeekCredential 默认的 base URL 是 https://api.deepseek.com _deepseek.py:12。 如果你走代理，只改 base_url 即可。

任意 OpenAI 兼容端点

from agentscope.credential import OpenAICredential
from agentscope.model import OpenAIChatModel

model = OpenAIChatModel(
    credential=OpenAICredential(

本地 Ollama

陷阱与窍门

看到 ModuleNotFoundError: No module named 'agentscope'

虚拟环境没激活，或装到了别的 Python 上。先 python -c "import sys; print(sys.executable)" 确认解释器路径，再 uv pip install。

看到 401 / AuthenticationError

key 没读到或已失效。os.environ["DEEPSEEK_API_KEY"] 在 key 不存在时会直接抛 KeyError，这比 401 更早暴露问题——所以示例故意用 [] 而不是 getenv。

看到 RuntimeError: Agent did not produce a final message

reply() 没有从事件流里取到最终 Msg _agent.py:379。 常见原因是循环被中断或超出上限；改用 reply_stream() 打印事件，能看到停在哪一步。

Windows 上的两个小问题

一是 PowerShell 里设置环境变量用 $env:NAME="..."，不是 export； 二是某些可选依赖需要编译工具链，先只用核心包，遇到再装。

自检三问

  1. 如果我把 toolkit 换成 Toolkit(tools=[...])，reply() 的返回值结构会变吗？为什么？
  2. stream=True 是模型层的默认值，为什么 reply() 还能返回一条完整消息？
  3. max_iters=50 限制的是「模型调用次数」还是「工具调用次数」？

20 分钟动手练习

  1. 把示例里的 system_prompt 改成「只用英文回答」，确认输出语言真的变了。
  2. 把 reply() 改成 reply_stream()，只打印 TEXT_BLOCK_DELTA 的 delta，观察首字延迟。
  3. 把 DeepSeekChatModel 换成 OllamaChatModel（本地已装 Ollama 的话），其余代码不动，确认能跑。
