25 · 实时语音

语音不是「把文字读出来」这么简单：要处理谁说完了、能不能打断、 用户到底听到了哪一句、模型会话断了怎么接。 这一章分三条路线讲：TTS 合成、ASR 转写、以及端到端的 RealtimeAgent。

读完你能做到

  • 用 TTS 合成音频，并区分标准模式与流式输入模式
  • 用 TTSMiddleware 给普通文本 Agent 加上语音输出
  • 用 OpenAI ASR 批量转写，知道 2.0.11 的实时 ASR 边界
  • 用 RealtimeAgent + LocalAudioTransport 跑通语音对话
  • 理解打断时的播放位置、上下文截断与不同模型的截断能力

先说为什么：三条路线，不是一套 API

路线 链路 延迟 适合
TTS 中间件 文本 Agent → TTS → 音频事件 中 已有文本 Agent，想加语音播报
ASR + 文本 Agent + TTS 录音 → 转写 → Agent → 合成 高 录音问答、会议纪要、离线批处理
端到端 Realtime 音频直接进出语音模型 低 实时对话、可打断、保留语气

三条路线的 API 不同，别指望一个 Agent 参数全包。 先想清楚你要的是「给文字回复配音」，还是「像打电话一样对话」。

TTS 模型：标准与流式输入

所有 TTS 模型都继承 TTSModelBase _tts_base.py:18， 用 realtime _tts_base.py:49 区分两种模式：

模式 调用 适合
标准 synthesize(text)，返回完整音频或分块流 一次拿到整段文本
流式输入 push(delta) 边生成边推，synthesize() 收尾 对接 LLM 的流式输出

2.0.11 内置的模型类：

类 说明
OpenAITTSModel_model.py:46tts-1 / tts-1-hd / gpt-4o-mini-tts，mp3 / wav / opus 等
DashScopeTTSModel_model.py:51Qwen3-TTS，标准模式
DashScopeRealtimeTTSModel_realtime_model.py:184Qwen3-TTS WebSocket 流式输入
DashScopeCosyVoiceTTSModel_cosyvoice_model.py:30CosyVoice-v3，标准 / 实时两种模式
GeminiTTSModelGemini 2.5 TTS，流式输出

直接合成：synthesize 与 push

import os

from agentscope.credential import OpenAICredential
from agentscope.tts import OpenAITTSModel


async def main() -> None:
    tts = OpenAITTSModel(
        credential=OpenAICredential(
            api_key=os.environ["OPENAI_API_KEY"],
        ),
        model="tts-1",
        parameters=OpenAITTSModel.Parameters(
            voice="alloy",
            response_format="mp3",
        ),
        stream=True,
    )

    async for chunk in await tts.synthesize("你好，世界！"):
        if chunk.content:
            print(chunk.content.source.media_type, chunk.is_last)

synthesize() _tts_base.py:187 的返回类型取决于 stream： False 返回单个 TTSResponse，True 返回异步生成器， 最后一个 chunk 的 is_last=True。

TTSResponse _tts_response.py:30 的 content 是一个 DataBlock，媒体类型在 content.source.media_type，例如 audio/mpeg、audio/wav、 audio/pcm;rate=24000。

流式输入

import os

from agentscope.credential import DashScopeCredential
from agentscope.tts import DashScopeRealtimeTTSModel


async def speak() -> None:
    tts = DashScopeRealtimeTTSModel(
        credential=DashScopeCredential(
            api_key=os.environ["DASHSCOPE_API_KEY"],
        ),
        model="qwen3-tts-flash-realtime",
        parameters=DashScopeRealtimeTTSModel.Parameters(voice="Cherry"),
        stream=True,
    )

    async with tts:
        await tts.push("你好，")
        await tts.push("今天过得怎么样？")
        final = await tts.synthesize()

push() _tts_base.py:112 追加文本并返回当前已可用的音频；synthesize() 结束并刷新剩余缓冲。

Qwen3 按 token，CosyVoice 按句子

DashScopeRealtimeTTSModel 通常每次 push() 都有音频； CosyVoice 实时模式要等服务端分句，未成句时可能返回空响应。 两种行为都正常，不要拿「每次 push 必须有音频」写死。

ASR：批量转写与实时接口

ASR 基类 ASRModelBase _asr_base.py:19 同时声明了批量与实时两种用法：

  • 批量：直接 transcribe(audio=..., filename=...)
  • 实时：push(audio) 分块，最后 transcribe() 收尾

但 2.0.11 只内置了 OpenAI 批量实现 _model.py:14； 实时接口留给自定义实现。 

import os
from pathlib import Path

from agentscope.asr import OpenAIASRModel
from agentscope.credential import OpenAICredential


async def transcribe(path: str) -> str:
    audio = Path(path)
    asr = OpenAIASRModel(
        credential=OpenAICredential(
            api_key=os.environ["OPENAI_API_KEY"],
        ),
        model="gpt-4o-mini-transcribe",
        parameters=OpenAIASRModel.Parameters(language="zh"),
    )
    response = await asr.transcribe(
        audio=audio.read_bytes(),
        filename=audio.name,
    )
    return response.content.text if response.content else ""

filename 不是装饰：批量 API 靠扩展名判断内存音频的格式。 transcribe() _asr_base.py:209 的最终响应 is_last=True， ASRResponse.content _asr_response.py:14 是 TextBlock 或 None。

language 用 ISO-639-1（如 zh）， prompt 可以引导专有名词。两者都放在 Parameters 里，也可以单次调用覆盖。

TTSMiddleware：给文本 Agent 配音

TTSMiddleware _tts_middleware.py:21 拦截 reply 流里的文本块，把合成音频作为 DataBlock 事件插回同一条流。

on_reply _tts_middleware.py:51 的行为取决于 TTS 模型：

TTS 模式 中间件行为
标准 等 TextBlockEndEvent 拿到完整文本，再 synthesize(text)
实时输入 每个 TextBlockDeltaEvent 调 push(delta)，结束事件时 synthesize() 收尾

音频事件是增量 base64：DataBlockStartEvent → 多个 DataBlockDeltaEvent → DataBlockEndEvent， 按 block_id 拼成完整音频。

标准模式首字延迟高

标准 TTS 要等模型把整段话生成完才开始合成。对话场景优先用实时输入， 或者让模型按短句输出。

端到端语音：RealtimeAgent 三件套

RealtimeAgent _agent.py:102 把语音对话拆成三个对象：

对象 职责 谁持有生命周期
RealtimeModelBase 维护模型 WebSocket，声明采样率与能力 RealtimeAgent
TransportBase 采集与播放音频、报告播放进度、打断淡出 开发者
RealtimeAgent 回合划分、打断、工具调用、事件产出、断线重连 开发者

模型会话和音频传输是分开的：客户端断开可以保留模型会话， 模型会话超时也不影响传输。换一个传输再调 reply_stream()， 对话历史仍在 agent.state 里。

最小可运行：模型 + Agent + 本地声卡

先装可选依赖（本地声卡依赖 PortAudio，Linux 需要 libportaudio2）： 

pip install "agentscope[realtime]"
import os

from agentscope.agent import RealtimeAgent
from agentscope.credential import DashScopeCredential
from agentscope.event import ReplyEndEvent, TextBlockDeltaEvent
from agentscope.realtime import (
    DashScopeRealtimeModel,
    LocalAudioTransport,
)

model = DashScopeRealtimeModel(
    model="qwen3.5-omni-plus-realtime",
    credential=DashScopeCredential(
        api_key=os.environ["DASHSCOPE_API_KEY"],
    ),
    parameters=DashScopeRealtimeModel.Parameters(voice="Tina"),
)

agent = RealtimeAgent(
    name="Friday",
    system_prompt="你是一个中文语音助手，回答尽量简短。",
    model=model,
)

transport = LocalAudioTransport(
    input_sample_rate=model.input_sample_rate,
    output_sample_rate=model.output_sample_rate,
)


async def main() -> None:
    async with agent, transport:
        async for event in agent.reply_stream(transport):
            if isinstance(event, TextBlockDeltaEvent):
                print(event.delta, end="", flush=True)
            elif isinstance(event, ReplyEndEvent):
                print()

采样率不要写死。DashScope 上行通常是 16 kHz，OpenAI 与 xAI 是 24 kHz； 直接用模型的 input_sample_rate / output_sample_rate 构造传输，换模型不会炸。

戴耳机，别外放

LocalAudioTransport 不做回声消除。外放时麦克风会录到智能体自己的声音， 回合检测会把它当用户开口，于是智能体不断打断自己。

事件流：用户轮次与智能体回复

reply_stream() _agent.py:394 产出的事件与文本 Agent 基本一致，但用户说话也算一次 reply：

事件 含义
ReplyStartEvent(role="user")用户开始说话
TextBlockDeltaEvent智能体文本，或用户转写
DataBlockDeltaEvent回复音频增量，通常已由传输播放
ToolCallStartEvent / ToolResultEndEvent工具调用与结果
RequireUserConfirmEvent工具调用需要确认
ReplyEndEvent一次回复结束；role 区分双方

用 reply_id 归集事件，不要把新事件都追加到最后一条消息： 工具调用后的续答与原回复共享同一个逻辑 reply_id。

打断与截断：用户听到哪里，上下文就保留到哪里

用户在回复播放期间开口，智能体会立即停止播放并取消模型侧回复。 关键在「停在哪里」：

  1. 传输的 clear_audio() 返回 PlayoutPosition _playout.py:6， played_ms 是这条回复实际播放到的毫秒数
  2. 智能体据此把上下文里的助手消息截到用户真正听到的部分 _agent.py:647
  3. 被打断的回复以 finished_reason=interrupted 结束
  4. 文本块的 TextBlockEndEvent.text _event.py:192 给出截断后的最终文本

为什么要这么麻烦？因为文本增量比音频先到。用户只听到半句话， 但前端可能已经收到整段文字；如果上下文保留完整回复，模型会「以为」用户听完了。

模型侧不一定能截断

智能体侧上下文一定会截断，但模型服务端取决于协议：OpenAI Realtime 接受显式截断， Gemini Live 由服务端处理，DashScope 与 xAI 不接受截断指令， 模型侧仍保留完整回复。跨模型对比时要考虑这个差异。

代码也可以主动打断，例如界面上的停止按钮： 

async def stop(agent) -> None:
    await agent.interrupt()

interrupt() _agent.py:541 等价于发送一个 UserInterruptEvent。

工具与确认：事件流不暂停

传入 toolkit 后，模型可以在语音对话中调用工具。 与文本 Agent 最大的区别是：确认不会暂停事件流。 

from agentscope.event import RequireUserConfirmEvent
from agentscope.tool import Bash, Read, Toolkit

agent = RealtimeAgent(
    name="Friday",
    system_prompt="你是一个中文语音助手。",
    model=model,
    toolkit=Toolkit(tools=[Bash(), Read()]),
)

async def run() -> None:
    async with agent, transport:
        async for event in agent.reply_stream(transport):
            if isinstance(event, RequireUserConfirmEvent):
                # 把确认请求交给界面，不要在这里阻塞事件流
                show_confirm_dialog(event)

用户做出选择后，用 send() _agent.py:490 送回 UserConfirmResultEvent。确认等待超时是 300 秒 _agent.py:1289， 超时按拒绝处理。

  • 只有模型卡片标注 supports_tools 的模型才收工具列表
  • 工具在智能体侧执行，权限检查与文本 Agent 一致
  • 实时语音不支持元工具 / 工具组，工具列表在连接时一次性发送

回合检测与 TurnAggregator

「用户什么时候说完了」只能由一方决定：

模式 配置 适用
模型 API 检测 不传 vad，用 Parameters.turn_detection 默认，无需额外模型
本地 VAD 传入 VADBase 实现 自定义端点策略，或 API 不提供检测 
from agentscope.realtime import SpeechTransition, VADBase


class MyVAD(VADBase):
    sample_rate = 16000  # 必须与传输的输入采样率一致

    def push(self, pcm: bytes) -> SpeechTransition | None:
        # 只在说话开始 / 结束的那一块返回 STARTED / ENDED
        return None

    def reset(self) -> None:
        # 音频流出现间断（例如重连）时清空内部状态
        pass

不管哪种模式，转写都会先经过 TurnAggregator _aggregator.py:8 整理： 

from agentscope.agent import RealtimeAgent, TurnAggregator

agent = RealtimeAgent(
    name="Friday",
    system_prompt="你是一个中文语音助手。",
    model=model,
    aggregator=TurnAggregator(
        merge_window_ms=800,
        backchannels=frozenset({"嗯", "好的"}),
        min_chars=1,
    ),
)
  • merge_window_ms：上一轮结束后多久内的转写并入上一轮，修「停顿被切成两句」
  • backchannels：纯应答不构成一轮，语言相关，默认空
  • min_chars：短于该长度的转写丢弃

断线重连：会话超时是常态

各家的实时会话都会主动关闭：DashScope 空闲超时约三分钟，Gemini Live 音频会话上限约 15 分钟，OpenAI Realtime 约一小时。智能体把它当正常情况处理：

  • 记录 INFO 日志，保持传输打开
  • 用户下一次说话时自动重连，并补发这期间的音频
  • 对话历史在 agent.state 中，重连时把此前转写附在系统提示后

supports_history_replay _base.py:43 标明模型是否支持这种历史补发；supports_text_input _base.py:40 标明能不能用 send("文字") 输入。

Qwen-Omni 不接受文本轮次

DashScopeRealtimeModel 的 supports_text_input=False _model.py:79， 调 send("...") 会抛 NotImplementedError。 需要文字输入就换模型，或在界面上隐藏输入框。

自定义传输：从声卡到浏览器

LocalAudioTransport 只适合本机调试。接浏览器或其他音频源时， 继承 TransportBase 实现：

方法 / 属性 作用
start() / close()打开与关闭设备或连接
incoming()产出上行 AudioFrame（PCM16）与控制帧
send_audio(pcm, item_id)播放一块模型音频
clear_audio()打断时丢弃未播放音频，返回 PlayoutPosition
playout当前播放位置

播放进度统计要尽量靠近扬声器。浏览器里应放在 AudioWorklet， 而不是在主线程估算，否则截断位置会偏。

官方 realtime 文档说浏览器传输「即将上线」，但 2.0.11 的 Agent Service 已经提供 WebRTC 协商端点。路径是：

端点 作用

延迟与成本：语音的隐藏账

RealtimeAgent.last_turn_metrics _agent.py:546 给出最近一轮的延迟拆解：

指标 含义
endpointing_delay_metrics.py:29判断「说完了」花了多久
backend_ttfb_metrics.py:34模型首字节延迟
transport_delay_metrics.py:42音频到扬声器的延迟
e2e_latency_metrics.py:50用户停止说话到听到回答

成本上，语音比文本贵得多：

  • PCM16 单声道 16 kHz 约 32 KB/s，24 kHz 约 48 KB/s；一小时通话是 100 MB 级
  • 实时模型按音频 token 计费，静音也会占会话时间
  • 转写文本会进入上下文，长对话照样触发压缩与 token 成本
  • 录音与转写都可能是敏感数据，存储前要脱敏、加密、设保留期

陷阱与窍门

把采样率写死

不同模型上行采样率不同。写死 16 kHz 接 OpenAI 会变调或失真， 永远用模型的 input_sample_rate / output_sample_rate。

外放导致自我打断

本地传输没有回声消除。戴耳机，或换带 AEC 的自定义传输。

以为打断会把模型侧上下文也截断

AgentScope 侧一定截断，模型侧看协议。DashScope 与 xAI 不支持截断指令， 模型仍记得完整回复。

在确认对话框里阻塞事件流

RequireUserConfirmEvent 之后事件流还要继续。确认放到界面回调， 用 agent.send() 异步送回，别在循环里 input() 死等。

用 Qwen-Omni 调 send("文字")

supports_text_input=False，会直接抛 NotImplementedError。先查模型能力再渲染输入框。

把整段文本当用户听到的内容

文本增量先于音频到达。打断时必须用 played_ms 截断上下文， 并用 TextBlockEndEvent.text 覆盖已经发出的文本。

文档与源码的小差异

realtime 文档提到模型类有 truncation 属性 （EXPLICIT / SERVER / NONE），2.0.11 源码里没有这个属性； 截断行为写在各模型实现里。以源码与实际模型为准。
