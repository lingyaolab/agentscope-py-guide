12 · 工作区与沙箱

前面几章的 Agent 一直在「说」。这一章给它一个真正能动的环境：读写文件、执行命令、安装依赖， 并且把这些动作限制在一个可管理、可持久化、可销毁的边界里。 工作区（Workspace）就是这个边界。

读完你能做到

  • 说清 Workspace / Backend / Tool 三层各自负责什么
  • 用 LocalWorkspace 把工具、卸载器和会话目录接进 Agent
  • 把同一份 Agent 代码切到 Docker / E2B / K8s，而不改业务逻辑
  • 解释沙箱里的 MCP 为什么要经过网关，以及 default_mcps 并不是共享实例

先说为什么：Agent 不能只「建议」改文件

没有工作区时，模型只能输出「请把 main.py 第 10 行改成…」。真正执行的是人。 一旦要让它自动改代码、跑测试、装依赖，就必须回答四个问题：

问题 工作区的回答
在哪执行？ workdir + Backend（本机 / 容器 / 云沙箱）
执行完的东西还在吗？ 持久化策略：主机目录、PVC、沙箱元数据
能碰主机吗？ 隔离边界：容器 / 沙箱 / 命名空间
资源什么时候销毁？ 生命周期：initialize / close / reset

AgentScope 提供七种工作区实现，共享同一套接口： LocalWorkspace、BubblewrapWorkspace、DockerWorkspace、 E2BWorkspace、DaytonaWorkspace、K8sWorkspace、 OpenSandboxWorkspace。

三层：Workspace / Backend / Tool

Workspace（生命周期与资源）
管 workdir、MCP 声明、技能目录、卸载文件；负责 initialize / close。
Backend（真正执行）
LocalBackend 在本机读写；DockerBackend / E2BBackend 等把命令送进隔离环境。
Tool（模型能调用的动作）
Bash / PowerShell / Read / Write / Edit / Glob / Grep，构造时绑定一个 backend。

WorkspaceBase _base.py:225 把方法分成四类：

角色 方法
生命周期 initialize()_base.py:494、close()_base.py:498、reset()_base.py:501、async with_base.py:533
资源发现 list_tools()、list_mcps()、list_skills()、get_instructions()
上下文卸载 offload_context()、offload_tool_result()、offload_data_block()
动态管理 add_mcp()、remove_mcp()、add_skill()、remove_skill()

LocalWorkspace：最小可用

LocalWorkspace _local_workspace.py:65 直接在本机目录上工作，是开发阶段最省事的选择。 

from agentscope.workspace import LocalWorkspace


async def build_workspace() -> LocalWorkspace:
    workspace = LocalWorkspace(
        workdir="/data/my-workspace",
        default_mcps=[],
        skill_paths=["./skills/web-search"],
    )
    await workspace.initialize()
    return workspace

目录布局是固定的：

{workdir}/
├── .mcp           # 按智能体 / 会话保存的 MCP 声明
├── data/          # 卸载的多模态内容，按 SHA-256 去重
├── skills/        # .seed 模板 + 按智能体隔离的技能目录
└── sessions/      # 各会话的 context.jsonl 与工具结果文件

initialize() _local_workspace.py:164 是幂等的：已经初始化过就什么都不做。它只创建目录、恢复 MCP 声明、准备技能种子， 不会真的连接 MCP——客户端在第一次 list_mcps 时才构建。

接入 Agent：三条资源线

工作区通过两条路径进入 Agent：资源来源，以及上下文卸载器。

from agentscope.agent import Agent
from agentscope.tool import Toolkit


async def build_agent(workspace, model) -> Agent:
    agent_id = "coder"
    session_id = "session-1"

    return Agent(
        name="coder",
        system_prompt="你是一个编程助手。",
        model=model,
        toolkit=Toolkit(
            tools=await workspace.list_tools(),
            mcps=await workspace.list_mcps(
                agent_id=agent_id,
                session_id=session_id,
            ),
            skills_or_loaders=await workspace.list_skills(agent_id=agent_id),
        ),
        offloader=workspace,
    )
接入点 给 Agent 什么
tools=await workspace.list_tools() 已绑定后端的内置工具
mcps=await workspace.list_mcps(agent_id, session_id) 按智能体 / 会话隔离的 MCP 客户端
skills_or_loaders=await workspace.list_skills(agent_id) 技能目录
offloader=workspace 压缩与截断时的持久化目标

沙箱：Docker / E2B / K8s

沙箱类工作区都继承 SandboxedWorkspaceBase _sandboxed_base.py:38， 比本地多出 gateway_port _sandboxed_base.py:55 与沙箱启动 / 销毁逻辑。

Docker

DockerWorkspace _docker_workspace.py:43 把主机 workdir 挂到容器内 /workspace。容器重启后文件还在； 不传 workdir 就是纯临时容器。 

from agentscope.workspace import DockerWorkspace


async def build_docker() -> DockerWorkspace:
    workspace = DockerWorkspace(
        base_image="python:3.11-slim",
        workdir="/data/docker-workspaces/agent-1",
        node_version="20",
        extra_pip=["numpy", "pandas"],
    )
    await workspace.initialize()
    return workspace

E2B

E2BWorkspace _e2b_workspace.py:66 以云沙箱文件系统为持久化层，没有主机 workdir；重启后按沙箱元数据重连。 

from agentscope.workspace import E2BWorkspace

workspace = E2BWorkspace(
    template="base",
    api_key="your-e2b-api-key",
    timeout_seconds=300,
)

Kubernetes

K8sWorkspace _k8s_workspace.py:55 为每个工作区起一个 Pod，并挂一个 PVC 做持久化。 

from agentscope.workspace import K8sWorkspace

workspace = K8sWorkspace(
    namespace="agentscope",
    image="python:3.11-slim",
    storage_size="1Gi",
)
Bubblewrap 不隔离网络

它不需要守护进程，但为了让 MCP 网关在多次 bwrap 执行之间可达， 必须共享主机网络命名空间。要网络隔离，用 Docker / K8s / 云沙箱。

生命周期：initialize / close / reset

三种终结方式的区别：

操作 做什么 数据还在吗
initialize() 创建目录 / 启动容器或 Pod / 恢复声明 是
close() 停止容器 / 关闭连接 / 释放临时资源 持久化目录 / PVC 还在
reset() 清空工作区内容，重新开始 否

async with _base.py:533 会自动调用 initialize 与 close，是最不容易漏掉清理的写法： 

from agentscope.workspace import LocalWorkspace

async def main() -> None:
    async with LocalWorkspace(workdir="./my-workspace") as workspace:
        tools = await workspace.list_tools()
        ...

沙箱类工作区的首次 initialize 可能很慢：OpenSandbox 要在沙箱内自举网关虚拟环境， 冷启动可能数分钟。这不是卡死。

工作区工具：list_tools 给了什么

LocalWorkspace.list_tools() _local_workspace.py:141 返回六个工具，全部绑定到工作区后端：

工具 说明
Bash / PowerShell Windows 自动用 PowerShell，其余用 Bash；cwd 是 workdir
Edit 精确字符串替换
Glob 按文件名搜索，默认搜索目录是 workdir
Grep 按内容搜索，默认搜索目录是 workdir
Read 按行读取，支持图片 / PDF
Write 创建或覆写文件

在沙箱类工作区上，这些工具在容器或沙箱内部执行，不是在主机上。 你自己写的工具想享受同样的隔离，就把后端传进去： 

from agentscope.tool import Bash

bash = Bash(backend=workspace.get_backend())

get_backend() _base.py:514 返回当前工作区绑定的执行后端。忘了传，自定义工具就会在主机上跑。

运行时资源：MCP 与技能

工作区不只是文件系统，它还管理两类资源：

资源 发现 动态增删
MCP list_mcps(agent_id, session_id)_base.py:605 add_mcp() / remove_mcp()
技能 list_skills(agent_id)_base.py:1204 add_skill() / remove_skill()

构造参数里的 default_mcps 和 skill_paths 是种子， 不是共享实例。每个智能体 / 会话在第一次访问时拿到自己的 MCP 客户端； 每个智能体从 skills/.seed 复制出自己的技能分区。

工具太多时，建议用 ToolGroup 分组，让模型按需激活，而不是一次性塞进 Toolkit。

MCP 网关：沙箱里的工具怎么出来

沙箱类工作区不能直接注册主机侧的 MCP 客户端：MCP 服务器在容器内部，stdio 会话跨不过边界。 解决办法是一个运行在沙箱内部的轻量 FastAPI 网关： 

主机                                     容器 / 云沙箱
┌──────────────┐                        ┌────────────────────┐
│ Agent        │   HTTPS + Bearer       │  MCP 网关 (FastAPI) │
│ Toolkit      │ ─────────────────────▶ │    ├─ MCP 1 (stdio) │
│ GatewayMCP.. │                        │    ├─ MCP 2 (http)  │
└──────────────┘                        │    └─ MCP N         │
                                        └────────────────────┘
  • 网关只监听沙箱回环地址，不对外发布端口
  • 每次 initialize() 生成工作区专属 Bearer 令牌
  • 主机侧用 GatewayMCPClient / GatewayMCPTool 适配，接口仍是 MCPClient
  • 主机到网关的调用通过后端的 exec_shell 发 curl，不是直接连端口

所以 list_mcps() 在所有后端上返回的都是 MCPClient 实例， 上层工具代码不需要知道「这个 MCP 在本地还是沙箱里」。

Bubblewrap 的两道额外防护

它共享主机网络命名空间，理论上主机上其他进程能看到回环端口。因此网关额外要求 Bearer 令牌，并在 /health 响应里带一个启动时生成的随机数，避免端口竞争泄露令牌。

选型：本地 / 容器 / 云沙箱

工作区 隔离 持久化 适合
LocalWorkspace 无 主机 workdir 本地开发、调试、单机工具
DockerWorkspace 容器 主机目录挂载到 /workspace 需要隔离又不想上云
K8sWorkspace Pod PVC 集群部署、多租户
E2B / Daytona / OpenSandbox 托管云沙箱 沙箱文件系统 不想自己运维容器 / 集群
BubblewrapWorkspace Linux 命名空间 主机目录挂到 /workspace Linux 上轻量隔离，无守护进程

陷阱与窍门

忘了 initialize() 就直接用

本地工作区可能只是目录不存在，沙箱类则根本没有容器 / Pod。统一用 async with，初始化与清理都不会漏。

用完不 close()

Docker 容器、K8s Pod、云沙箱都会残留。尤其 K8s，PVC 不删会一直计费。 临时环境用 async with，长期环境也要在应用退出时显式关闭。

自定义工具忘了传 backend

Bash() 不传 backend 就用本地执行。在沙箱工作区里， 这等于把命令放回主机跑，隔离形同虚设。用 Bash(backend=workspace.get_backend())。

以为 default_mcps 是共享实例

它是种子。每个智能体 / 会话第一次访问时拿到独立客户端。想让多个会话共享同一个状态连接， 需要自己在主机侧管理 MCPClient，而不是依赖工作区的种子。

在 Windows 上找 Bash

LocalWorkspace.list_tools() 在 Windows 上返回 PowerShell， 不是 Bash。写死工具名做判断时要注意这一点。

工具太多就用 ToolGroup

工作区会把所有工具平铺出来。超过十几个时，模型选择成本明显上升。 按用途分组，让模型通过元工具按需激活，只保留 basic 组常驻。
