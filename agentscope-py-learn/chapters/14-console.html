14 · 终端 Console

前面十几章都在写代码，但调试 Agent 时最缺的往往不是代码，而是看得见它在干什么。 这一章讲两个终端入口：agentscope.console 逐行打印，只依赖核心包； agentscope.tui 基于 Textual 提供全屏界面。

读完你能做到

  • 用 launch_console 在终端里和 Agent / 流水线对话，不写任何 UI 代码
  • 用 ConsoleRenderer 把事件流嵌进自己的脚本，并控制输出详细程度
  • 知道 y / a / 其他输入分别代表什么
  • 在 Console、TUI 与 Web 服务之间做出正确选择

先说为什么：不是所有调试都要起 Web

Agent 的问题大多出在「事件顺序」和「工具调用」上，而不是缺少一个漂亮的聊天框。 起一个 Web 服务、配前端、接 SSE，成本远高于收益。终端界面把这三件事做到最小：

需求 终端怎么解决
看事件流 逐行渲染文本、思考、工具调用、结果、token 用量
处理工具确认 直接在当前进程里读 y / a / 其他
中断 Ctrl+C 取消当前回复

两个模块的分工：

接口 模块 特点
launch_console_console.py:105 agentscope.console 逐行输出，核心依赖即可
ConsoleRenderer_renderer.py:78 agentscope.console 只渲染，不接管输入与循环
launch_tui_launcher.py:309 agentscope.tui Textual 全屏，Markdown 与表单
launch_realtime_ui_launcher.py:329 agentscope.tui 实时语音会话

launch_console：零界面代码

import asyncio

from agentscope.agent import Agent
from agentscope.console import launch_console
from agentscope.tool import Bash, Read, Toolkit, Write


async def main() -> None:
    agent = Agent(
        name="Friday",
        system_prompt="You're a helpful assistant.",
        model=model,
        toolkit=Toolkit(tools=[Bash(), Read(), Write()]),
    )
    await launch_console(agent)


asyncio.run(main())

它接收一个构造完成的 Agent，或任何满足 PipelineProtocol 的流水线， 然后接管输入循环：

环节 行为
输入 以 user> 提示符读取；exit / quit / Ctrl+D 退出_console.py:158
流式渲染 文本与思考实时打印，工具调用与结果整块输出
工具确认 逐个询问，处理完再继续_console.py:168
中断 Ctrl+C 取消当前回复_console.py:53

参数只有四个：

参数 默认 说明
agent必填Agent 或 PipelineProtocol
user_name"user"发送者名称，同时是输入提示符
verbosity"default"输出详细程度
max_tool_result_lines20工具结果最多打印多少行；None 不截断
它没有会话管理与持久化

对话只存在 agent.state 里，进程退出就结束。要多用户、多会话、持久化， 用 Agent Service（15 章），不是 Console。

ConsoleRenderer：把事件流变成终端输出

当你自己掌控循环（多智能体流水线、测试脚本），只需要渲染，不需要输入框，就用 ConsoleRenderer _renderer.py:78。 它是被动的： 

from agentscope.console import ConsoleRenderer
from agentscope.message import UserMsg

renderer = ConsoleRenderer()

async def run(agent) -> None:
    async for event in agent.reply_stream(
        UserMsg(name="user", content="你好！"),
    ):
        renderer.render(event)

    final_msg = renderer.last_msg
成员 作用
render(event)_renderer.py:146渲染一条事件
last_msg_renderer.py:131事件累积出的完整回复
verbosity详细程度

它按 reply_id 区分事件归属，所以多个 Agent 顺序发言时可以复用同一个实例： 上一个 Agent 的 last_msg 直接作为下一个的输入。

各类内容的渲染方式：

内容 渲染
文本 / 思考实时流式；思考用暗色
工具调用 / 结果结束事件到达时整块打印，并发结果不交错
提示块带边框面板
二进制数据占位符，如 [data: image/png, ~34KB]，不打印 base64
token 用量每次模型调用结束打印一行
渲染器不处理确认

遇到 RequireUserConfirmEvent 或外部执行事件，它只显示提醒。 收集结果并把事件传回，是调用方的事（08 章）。

三档详细程度

Verbosity _renderer.py:40 有三个值：

档位 显示 适合
quiet 只有回复文本与错误 演示、截图、CI 输出
default + 思考、工具调用与结果、提示块、token、确认提醒 日常调试
debug + 生命周期事件（模型调用开始、结束原因）与工具结果元数据 排查事件顺序、确认挂起

未知事件类型会被静默跳过；debug 档会打印类型名。这意味着事件协议新增类型时， 旧渲染器不会崩。

交互：输入、确认与中断

工具确认提示长这样： 

Allow 'Bash'? [y]es / [N]o / [a]lways
输入 行为
y / yes 允许这一次
a / always 允许，并接受建议规则；本进程内匹配的调用不再询问_console.py:88
其他 拒绝；模型会收到 DENIED 结果
Ctrl+C（确认处） 放弃挂起的回复，发 UserInterruptEvent_console.py:175
Ctrl+C（流式中） 取消当前回复；Agent 走 13 章的清理逻辑
a 只在本进程有效

接受的规则写在 agent.state.permission_context 里，进程退出就没了。 要长期保留，把状态存到 Redis / SQL（13 章）。

launch_tui：全屏 Markdown 与表单

需要更好的阅读体验时用 launch_tui _launcher.py:309。 它依赖 Textual，先装扩展： 

pip install "agentscope[tui]"
import asyncio

from agentscope.tui import launch_tui
from agentscope.tool import AskUser, Toolkit
from agentscope.workspace import LocalWorkspace


async def main() -> None:
    async with LocalWorkspace(workdir="./workspace") as workspace:
        agent = Agent(
            name="Friday",
            system_prompt="You are a helpful assistant.",
            model=model,
            toolkit=Toolkit(
                tools=[AskUser(), *(await workspace.list_tools())],
            ),
            offloader=workspace,
        )
        await launch_tui(agent)


asyncio.run(main())
环节 行为
输入Enter 发送，Shift+Enter 换行，/exit 退出
渲染Markdown 实时渲染；工具与思考折叠，Enter 展开
确认↑/↓ 在「允许一次 / 按规则始终允许 / 拒绝 / 中断」间选择
AskUser表单呈现，支持单选、多选、预览与「其他」自由输入
中断回复中按 Ctrl+C

回复进行中，输入框仍然可用：新消息会排队，按顺序逐个调用 reply_stream， 不会并发修改同一个 Agent 的上下文。

退出命令不一样

launch_console 用 exit / quit； launch_tui 用 /exit。写自动化脚本时别弄混。

实时语音界面

实时语音的输入是持续音频流，因此用单独的 launch_realtime_ui _launcher.py:329。 它只借用 Agent 与传输，两者都要你先启动，界面退出也不会替你关闭。 

from agentscope.tui import launch_realtime_ui


async def run_voice(agent, transport) -> None:
    async with agent, transport:
        await launch_realtime_ui(agent, transport)
  • 只显示双方转写文本、工具调用与确认卡片；音频本身由传输播放，不进界面
  • 开口说话即可打断；界面发起的中断以 UserInterruptEvent 经 agent.send() 送达
  • 模型支持文字输入时才有输入框，否则只能说话

嵌入自己的应用：ChatUI / MessagesUI

已有 Textual 应用时，可以直接用两个组件：

组件 内容
MessagesUI 只读消息列表，渲染 Markdown、工具调用与附件
ChatUI 在消息列表上增加输入框、确认与 AskUser 表单

ChatUI 通过 Textual 消息把用户操作发出来： Submitted、Confirmed、 ExternalExecutionSubmitted、InterruptRequested。 你的运行时负责消费这些消息，并把事件应用到 Msg 上。

流式更新用 update_message()，初始加载或整体替换用 set_messages()。 直接改原来的 Msg 对象不会刷新界面。

Console vs TUI vs Web 服务

场景 用什么 原因
本机快速试一个 Agent launch_console 零 UI 代码，核心依赖即可
自己的脚本 / 测试里看事件 ConsoleRenderer 只渲染，不抢循环
更好的阅读与交互 launch_tui Markdown、折叠、表单
多用户、多会话、持久化 Agent Service Console / TUI 都不管存储
浏览器访问、SSE 推送 Agent Service + 前端 15、16 章

陷阱与窍门

import agentscope.tui 直接报错

没装 Textual。按提示执行 pip install "agentscope[tui]"， 或直接用 agentscope.console（核心依赖就够）。

以为 Console 会保存对话

它没有会话管理。进程退出后上下文、已接受的权限规则、任务清单全没了。 要持久化，用 13 章的 AgentState 或 Agent Service。

Ctrl+C 没有触发清理

Console 依赖 interruption_raise_cancelled_error=False（默认）。 如果你改成了 True，取消异常会继续向外抛，Console 的收尾行为会不同。

在 ConsoleRenderer 里等确认

它只显示提醒，不会替你读输入。需要交互就用 launch_console / launch_tui， 或者自己实现确认循环。

用 verbosity="debug" 排查挂起

Agent 停在确认上时，default 档只显示提醒。切到 debug 能看到生命周期事件与结束原因，快速判断是「在等确认」还是「真的卡住」。

二进制内容不会打印 base64

图片、音频只显示占位符和大小。要检查实际内容，去工作区的 data/ 目录找文件。
