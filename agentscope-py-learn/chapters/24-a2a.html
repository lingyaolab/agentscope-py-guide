24 · A2A 协议

前 23 章都在讲「自己家的 Agent 怎么跑」。但真实系统里，Agent 往往由不同团队、 不同框架、甚至不同公司提供。A2A（Agent2Agent）就是让它们互相说话的最小协议。 这一章讲 AgentScope 的 A2AAgent 怎么接远端，以及怎么把自己暴露出去。

读完你能做到

  • 用 A2ACardResolver 取回 Agent Card 并创建 A2AAgent
  • 分清 context_id 与 task_id，知道什么时候会续接 Task
  • 看懂 Message / Artifact / Status / Task 四种载荷的转译与结束原因
  • 用 A2AAgentState 持久化并续接一段远端会话
  • 用官方 a2a-sdk 把 AgentScope Agent 暴露成 A2A 服务端

先说为什么：为什么不用 HTTP 包一层

你当然可以自己定一套 HTTP JSON：POST /chat，返回一段文本。 但一旦要跨团队，问题就来了：

自己包 HTTP A2A
对方怎么发现你的能力？ Agent Card 自描述：名称、能力、传输方式、技能
流式输出怎么表达？ Artifact 分块 + append / last_chunk
多轮会话怎么串？ context_id
远端要你补充信息怎么办？ Task 状态 INPUT_REQUIRED
换框架还能互通吗？ 按 A2A 1.0 规范，官方 SDK 还兼容 0.3

A2A 不替代 MCP：MCP 是 Agent 用工具，A2A 是 Agent 找 Agent。 一个是纵向接能力，一个是横向接协作。

Agent Card：远端的自描述

Agent Card 是一份放在固定地址上的 JSON，告诉客户端：我是谁、支持什么传输、 能不能流式、有哪些技能。客户端先取卡片，再决定怎么连。 

{
  "name": "Friday",
  "description": "An AgentScope assistant exposed over A2A 1.0.",
  "version": "1.0.0",
  "supportedInterfaces": [
    {
      "url": "http://127.0.0.1:9999",
      "protocolBinding": "JSONRPC",
      "protocolVersion": "1.0"
    }
  ],
  "capabilities": {"streaming": true},
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [
    {
      "id": "chat",
      "name": "Chat",
      "description": "Answer questions in a multi-turn conversation.",
      "tags": ["chat"]
    }
  ]
}

卡片里的 name 会成为 A2AAgent.name； capabilities.streaming 决定能不能走流式； supportedInterfaces 决定传输绑定。

卡片是远端写的，不是可信配置

名称、描述、技能都会进入你的界面甚至提示词。把它当外部输入处理： 展示前转义、不要直接拼进系统提示、对 URL 做 allowlist。

连接：解析卡片并创建 A2AAgent

A2A 支持放在可选依赖里，安装： 

pip install "agentscope[a2a]"

对应的 extra 是 a2a-sdk>=1.1.1 pyproject.toml:124。 没装时创建 A2AAgent 会直接提示安装命令 _a2a_agent.py:235。 

import httpx
from a2a.client import A2ACardResolver

from agentscope.agent import A2AAgent
from agentscope.console import ConsoleRenderer
from agentscope.message import UserMsg


async def main() -> None:
    async with httpx.AsyncClient() as http:
        card = await A2ACardResolver(
            httpx_client=http,
            base_url="http://127.0.0.1:9999",
        ).get_agent_card()

    renderer = ConsoleRenderer()
    async with A2AAgent(card) as remote:
        async for event in remote.reply_stream(
            UserMsg(name="user", content="帮我规划一个杭州周末行程。"),
        ):
            renderer.render(event)

        print(renderer.last_msg.get_text_content())

不传 client 时，A2AAgent 会按卡片自建一个流式客户端， 要求对方提供 JSONRPC 或 HTTP+JSON 接口 _a2a_agent.py:245。 需要 gRPC 或自定义鉴权时，自己构造官方 SDK 客户端，用关键字参数传进去。

A2AAgent _a2a_agent.py:189 刻意不继承 Agent：它没有模型、工具、权限和推理循环， 只持有远端会话与 Task。接口对齐，但语义不同。

一个实例只服务一段对话，关闭后不能重开

A2AAgent 自己持有 A2A 客户端，并在 aclose() 里关闭 _a2a_agent.py:277。 要开新会话，重新创建实例。

context_id 与 task_id：最容易混淆的两个标识

标识 含义 AgentScope 侧
context_id 远端的一段会话 相当于 session_id，多次 reply() 自动携带
task_id 远端的一次执行单元 不等于一次 reply：可能跨多个 Task，也可能续上旧 Task
session_id 本地事件分组用 只属于适配器，与远端无关

三者都在 A2AAgentState 里 _a2a_state.py:10。 task_id 只在远端等待输入时保留 _a2a_agent.py:179； 下一条消息会续上它，否则在同一 context_id 内开新 Task。

发送前如果本地还记着 task_id，适配器会先向远端查这个 Task：

远端状态 适配器行为
仍在 SUBMITTED / WORKING 直接抛 RuntimeError，因为再发会让它重复执行 _a2a_agent.py:392
INPUT_REQUIRED / AUTH_REQUIRED 保留 task_id，下一条消息续接
其他终态 清空 task_id，开新 Task
远端已忘记（TaskNotFoundError） 清空 task_id，降级为新 Task

这就是为什么「重试一次 reply()」并不总是安全：如果远端还在跑， 第二次发送会被拒绝；如果远端已经完成，第二次发送会开新 Task。

四种响应载荷怎么转译

A2A 载荷 转译 对 task_id 的影响
Message Parts 转内容；这是一次不产生 Task 的直接回答 清空
TaskArtifactUpdateEvent 制品 Parts 转内容，append / last_chunk 决定文本块是否续写 不影响
TaskStatusUpdateEvent 状态消息 Parts 转内容，同时决定结束原因 等待输入时保留，否则清空
Task 完整快照：先全部制品，再状态消息 同上

载荷分派在 _a2a_agent.py:324。 最终消息的 metadata["a2a"] 记录 context_id； 块结束事件的 metadata 记录它来自哪个 task_id / artifact_id / message_id，排障时很有用。

内容 Part：只支持文本、字节与 URL

A2A Part AgentScope 块 说明
文本 Part TextBlock 同一批连续文本流入同一个块
raw 字节 Part DataBlock 字节以 base64 承载
url Part DataBlock 保留原始 URL
结构化数据 Part 不支持 抛 ValueError

发送方向也一样：只接受 TextBlock 与 DataBlock， 其他块类型直接抛 TypeError _a2a_agent.py:550。 所以不要把带工具调用、思考块或 hint 的消息直接发给 A2AAgent。

结束原因：远端挂起，本地不挂起

这是 A2A 与本地 Agent 最大的语义差异：远端 Task 可能停在 INPUT_REQUIRED，但本地没有任何东西被挂起。 因此每一次响应流结束都意味着本次 reply 结束， 只是结束原因不同：

远端 Task 状态 finished_reason 下一步
COMPLETED COMPLETED 可以开新话题
INPUT_REQUIRED / AUTH_REQUIRED COMPLETED 状态消息就是远端的问题，用下一次 reply() 回答
CANCELED INTERRUPTED 任务被取消
FAILED / REJECTED ERROR 失败或被拒绝

映射在 _a2a_agent.py:157。 注意 INPUT_REQUIRED 在本地是「正常完成」， 不是 HITL 暂停；要回答远端的问题，直接再调一次 reply()。

AUTH_REQUIRED 不能在本适配器里批准

A2A 的凭据走协议之外。适配器只会把状态消息当普通内容返回， 不会提供授权入口；需要按消息里的指引在外部完成。

状态持久化：续接一段远端会话

A2AAgentState 只有四个字段 _a2a_state.py:10：

字段 作用
session_id_a2a_state.py:13本地事件分组
context_id_a2a_state.py:16续接远端会话
task_id_a2a_state.py:19续接等待输入的 Task
observed_context_a2a_state.py:22尚未发出去的历史消息
 
from agentscope.agent import A2AAgent
from agentscope.state import A2AAgentState

# 从数据库里取回上次保存的 context_id
stored = A2AAgentState(
    context_id="ctx-123",
    task_id=None,
)

agent = A2AAgent(card, state=stored)

只保存 context_id 就能续上多轮；如果上次远端停在 INPUT_REQUIRED，再保存 task_id 才能续上那个具体 Task。 observed_context 里是还没发出去的消息，通常不需要持久化。

observe：把历史塞进下一次输入

本地 Agent 的 observe() 是写入上下文； A2AAgent 的 observe() 只是缓存， 等下一次 reply() 时一起发送 _a2a_agent.py:646。 

from agentscope.message import UserMsg


async def ask(remote) -> None:
    await remote.observe(
        [
            UserMsg(name="user", content="我下个月去杭州。"),
            UserMsg(name="assistant", content="好的，记下了。"),
        ],
    )
    reply = await remote.reply(
        UserMsg(name="user", content="那周末怎么安排？"),
    )
    print(reply.get_text_content())

如果这次发送在预检阶段就被拒绝，缓存不会清空，方便重试； 一旦真正发出，缓存就清空。

compress_context() 是空操作 _a2a_agent.py:630： 上下文归远端管，本地没有可压缩的东西。

服务端：把 AgentScope Agent 暴露为 A2A

核心包只提供客户端 A2AAgent；没有把 A2A 服务端集成进 create_app。要对外提供 A2A，用官方 a2a-sdk 的服务端原语， 把 AgentScope 的 reply 流桥接过去。

先定义 Agent Card 和路由： 

from a2a.server.request_handlers import DefaultRequestHandler
from a2a.server.routes import create_agent_card_routes, create_jsonrpc_routes
from a2a.server.tasks import InMemoryTaskStore
from a2a.types import (
    AgentCapabilities,
    AgentCard,
    AgentInterface,
    AgentSkill,
)
from starlette.applications import Starlette


def create_a2a_app(executor, base_url: str) -> Starlette:
    card = AgentCard(
        name="Friday",
        description="An AgentScope assistant exposed over A2A 1.0.",
        version="1.0.0",
        supported_interfaces=[
            AgentInterface(
                url=base_url,
                protocol_binding="JSONRPC",
                protocol_version="1.0",
            ),
        ],
        capabilities=AgentCapabilities(streaming=True),
        default_input_modes=["text/plain"],
        default_output_modes=["text/plain"],
        skills=[
            AgentSkill(
                id="chat",
                name="Chat",
                description="Answer questions in a multi-turn conversation.",
                tags=["chat"],
            ),
        ],
    )
    handler = DefaultRequestHandler(
        agent_executor=executor,
        task_store=InMemoryTaskStore(),
        agent_card=card,
    )
    return Starlette(
        routes=[
            *create_agent_card_routes(card),
            *create_jsonrpc_routes(handler, rpc_url="/"),
        ],
    )

这段对应上游 examples/a2a/server.py server.py:129。 InMemoryTaskStore 只适合单进程演示；生产要换成持久化实现。

Task 生命周期与流式 Artifact

服务端的核心是一个 AgentExecutor：每个 context_id 一个 AgentScope Agent，保证并发会话互不串味。 

from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.tasks import TaskUpdater
from a2a.types import Part, Task, TaskState, TaskStatus

from agentscope.event import TextBlockDeltaEvent
from agentscope.message import UserMsg


class AgentScopeExecutor(AgentExecutor):
    def __init__(self, agent_factory):
        self._agent_factory = agent_factory
        self._agents = {}

    async def execute(
        self,
        context: RequestContext,
        event_queue: EventQueue,
    ) -> None:
        agent = self._agents.setdefault(
            context.context_id,
            self._agent_factory(),
        )

        await event_queue.enqueue_event(
            Task(
                id=context.task_id,
                context_id=context.context_id,
                status=TaskStatus(
                    state=TaskState.TASK_STATE_SUBMITTED,
                ),
            ),
        )
        updater = TaskUpdater(
            event_queue,
            task_id=context.task_id,
            context_id=context.context_id,
        )
        await updater.start_work()

        artifact_id = f"{context.task_id}-reply"
        pending = None
        started = False
        async for event in agent.reply_stream(
            UserMsg(name="user", content=context.get_user_input()),
        ):
            if not isinstance(event, TextBlockDeltaEvent):
                continue
            if pending is not None:
                await updater.add_artifact(
                    [Part(text=pending)],
                    artifact_id=artifact_id,
                    append=started,
                    last_chunk=False,
                )
                started = True
            pending = event.delta

        if pending is not None:
            await updater.add_artifact(
                [Part(text=pending)],
                artifact_id=artifact_id,
                append=started,
                last_chunk=True,
            )
        await updater.complete()

    async def cancel(self, context, event_queue):
        await TaskUpdater(
            event_queue,
            task_id=context.task_id,
            context_id=context.context_id,
        ).cancel()
  • Task 必须先 enqueue_event，否则后续 update 没有归属
  • start_work() / complete() / cancel() 负责状态迁移
  • 每个文本 delta 先攒着，下一个 delta 到时才发上一个， 这样最后一个能标 last_chunk=True
  • 只转译 TextBlockDeltaEvent；工具、思考、hint 不会发给 A2A 客户端

上游实现见 server.py:41。 Agent 映射在内存字典里，所以这个示例是单进程的；多副本部署需要把会话状态外置， 或者按 context_id 做粘性路由。

不支持的能力：工具、思考、HITL 与推送

能力 A2AAgent 说明
模型 / 工具 / 中间件 / 权限不提供全部由远端决定
结构化输出不提供协议侧没有对应表达
思考块 / 工具调用块 / hint不转译A2A 只传最终产物
HITL 暂停与恢复不提供INPUT_REQUIRED 以普通回复呈现
Push Notification不支持适配器只处理同步流
本地上下文压缩空操作远端拥有上下文

这不是「缺功能」，而是边界：A2A 是 Agent 之间的最终产物交换， 不是把远端 Agent 的内部执行过程搬到本地。

安全：卡片、凭据与不可信输出

  • 出站 SSRF：不要把用户输入的 URL 直接交给 A2ACardResolver；按域名 allowlist 限制。
  • 卡片投毒：name / description / skills 都可能带提示注入，展示与拼接前要清洗。
  • 凭据：A2A 的凭据在协议之外，别把 API key 塞进消息 Part； 自定义 client 走正规鉴权头或 mTLS。
  • 远端输出：把它当不可信内容；如果本地还要用工具处理， 先过权限系统与沙箱。
  • 服务端：官方示例没有鉴权与限流，对外前要自己在 Starlette / 网关上补。
A2A 不是信任边界

协议只负责消息格式，不负责「对方可信」。跨组织调用时， 身份认证、配额、内容审核都要你自己加。

生产注意：多副本、超时与幂等

问题 做法
客户端超时，远端还在跑 不能立刻重发；先查 task_id，仍在运行就等待或取消
重试导致重复执行 服务端按 task_id / message_id 做幂等
多副本丢内存 Agent 状态外置，或按 context_id 粘性路由
TaskStore 重启丢失 演示用 InMemoryTaskStore，生产换持久化实现
长任务拖住连接 流式 artifact + 超时；必要时改推送模式（本适配器不支持）
大文件传输 用 URL Part 而不是 base64 raw，减少消息体积

A2AAgent 的事件流也适合接第 21 章的追踪：给远端调用加自定义 span， 把 context_id / task_id 写进属性，跨组织排障会轻松很多。

陷阱与窍门

把 task_id 当成 reply id

一次 reply 可能跨多个 Task，也可能续上旧 Task。持久化时 context_id 必存，task_id 只在等待输入时才有意义。

远端还在跑就重发

适配器会直接抛 RuntimeError，因为再发会让远端重复执行。 正确做法是等待、查询或取消，不是无脑重试。

把工具调用消息发给 A2AAgent

只支持文本与 DataBlock；ToolCallBlock / ThinkingBlock 会直接抛 TypeError。

以为 INPUT_REQUIRED 是本地暂停

本地没有任何挂起状态，这次 reply 已经结束；远端的问题就在状态消息里， 用下一次 reply() 回答。

在多副本里用内存 Agent 字典

上游服务端示例按 context_id 存 Agent 实例，只适合单进程。 多副本要外置状态或做粘性路由，否则同一会话会丢上下文。

把 Agent Card 当可信配置

卡片来自远端，名称与描述都可能被投毒。展示、拼接提示词、决定路由前都要校验。

文档说 reply_stream 不支持 yield_final_msg

2.0.11 源码已经支持这个参数 _a2a_agent.py:283， 以源码为准；用 renderer.last_msg 或 reply() 也同样可行。
