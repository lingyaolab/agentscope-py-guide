19 · MCP 与技能中心

18 章把 Agent 放进了 IM，用户开始真正使用它。接下来用户会问： 「能不能接我的 Notion？」「能不能装一个写周报的技能？」 中心（Hub）就是这两个问题的答案：可浏览的资源目录 + 安装 + 装配。

读完你能做到

  • 说清 Hub、Card、资源池、工作区四者的关系
  • 用 create_app(mcp_hubs=..., skill_hubs=...) 启用中心
  • 解释为什么「安装」和「装配」必须分成两步
  • 写出一个按用户过滤可见性的自定义中心，并知道要在哪些方法里都过滤

先说为什么：不要让用户手写配置

没有中心时，用户要接一个 MCP 服务，得自己找 JSON、拼 command / url、填环境变量； 要装技能，得克隆仓库、找到 SKILL.md、再上传文件夹。中心把这套流程产品化：

没有中心 有中心
用户手写 MCP 配置 浏览目录，点安装，按表单填凭证
每个会话重复填密钥 凭证存进资源池，装一次用多处
不知道有哪些技能 搜索、看说明、看 SKILL.md 再装
平台新增服务要重新部署 中心目录更新即可，服务不用动

Hub / Card / 资源池 / 工作区

概念 说明
Hub_base.py:10 一个可浏览的目录，用 hub_id 在路由里寻址；生命周期与进程同长
Card 目录里的一个条目，是模板，不是可直接连接的配置
资源池 用户已安装的 MCP / 技能，属于用户而不是会话
工作区 装配目标：MCP 进 workspace 的 MCP 列表，技能进 skills 分区

最关键的一句话：安装 ≠ 装配。

MCP 中心：卡片与安装

MCPHubBase _base.py:9 只有两个抽象方法：

方法 作用
list_mcps(user_id, q, cursor, limit)浏览一页条目，游标分页
get_mcp(user_id, card_id)取单个条目；不存在抛 KeyError → 404

MCPCard _card.py:10 描述一个服务：

字段 说明
hub_id_card.py:29 / id_card.py:34全局定位一个条目
name / display_name / description展示信息
is_stateful_card.py:132是否维持长连接
auth_card.py:141none 或 inputs
inputs_schema_card.py:152用户要填的字段，JSON Schema
config_template_card.py:163带 ${placeholder} 的 Stdio / HTTP 配置模板

内置来源是 GitHubMCPHub _github_hub.py:101， 指向 GitHub MCP Registry，匿名可用。

用户点安装时，前端根据 inputs_schema 生成表单；提交后服务会立刻尝试连接， 凭证填错会当场在表单上报错，而不是装出一个用不了的条目。

技能中心：SKILL.md 与安装

SkillHubBase _base.py:26 有三个抽象方法：

方法 作用
list_skills(...)浏览一页条目，不带 SKILL.md 正文
get_skill(...)取单个条目，带上 SKILL.md
download(...)返回 SkillArchive(format, stream)，流式读取压缩包

SkillCard _card.py:8 的 markdown _card.py:113 就是 SKILL.md 正文；用户可以读完再决定装不装。 内置来源是 ClawSkillHub _claw_hub.py:75。

技能安装不需要填任何内容，只是加入资源池。装配时才把压缩包拉下来解压到工作区。

装配来源 行为
从已安装技能那一刻从中心拉取压缩包并解压
上传本地文件夹根目录必须包含 SKILL.md；最多 100 文件、单文件 50 MB、总计 500 MB

文件夹重名时会加数字后缀，不会覆盖已有技能。

注册中心

用 create_app 的两个参数 mcp_hubs _app.py:122 与 skill_hubs _app.py:123： 

from agentscope.app import create_app
from agentscope.app.hub import ClawSkillHub, GitHubMCPHub

app = create_app(
    storage=storage,
    message_bus=message_bus,
    workspace_manager=workspace_manager,
    mcp_hubs=[GitHubMCPHub()],
    skill_hubs=[ClawSkillHub()],
)
  • 不传对应参数 → 该类型中心关闭，但用户仍可手动粘贴 MCP 配置 / 上传技能文件夹
  • 可以注册多个，用不同 hub_id 区分
  • 同一类型下 hub_id 重复，服务启动时直接报错
  • Hub 在 lifespan 里进入一次，可以持有 HTTP 客户端复用连接

安装与装配：为什么分两步

浏览中心
   │
   ├─ 安装 ──▶ 用户资源池（凭证存这里）
   │              │
   │              ├─ 装配到工作区 A ──▶ 智能体 A 可用
   │              ├─ 装配到工作区 B ──▶ 智能体 B 可用
   │              └─ ...
   │
   └─ 不安装，只看
步骤 发生在哪 产生什么
安装 用户的资源池 一条已配置的 MCP / 技能记录，凭证只填一次
装配 某个智能体的工作区 MCP 客户端 / 技能目录，工具对智能体可见

分开的好处：同一个 MCP 装配到十个工作区，不会问十次密钥；资源池属于用户， 不会随会话结束而消失；删除已安装的 MCP 也不影响已经用上它的会话。

卡片：模板与输入项

MCP 卡片的核心是「用占位符描述配置，用 JSON Schema 描述输入」： 

MCPCard(
    hub_id=self.hub_id,
    id="weather",
    name="weather",
    display_name="Weather",
    description="实时天气与预报。",
    config_template=HttpMCPConfig(
        url="https://weather.example.com/mcp",
        headers={"Authorization": "Bearer ${api_key}"},
    ),
    inputs_schema={
        "type": "object",
        "required": ["api_key"],
        "properties": {
            "api_key": {
                "type": "string",
                "title": "API 密钥",
                "writeOnly": True,
                "format": "password",
            },
        },
    },
)
凭证字段必须 writeOnly + password

前端据此渲染密码框，并在用户再次编辑时留空。漏标会让密钥回传到浏览器。

${placeholder} 在任意字符串里都有效：URL、请求头、环境变量、命令行参数。

自定义中心

自定义 MCP 中心

from agentscope.app.hub import MCPCard, MCPHubBase, MCPHubPage


class InternalMCPHub(MCPHubBase):
    def __init__(self) -> None:
        super().__init__(
            hub_id="internal",
            display_name="内部 MCP 目录",
            description="由平台团队审核发布的 MCP 服务。",
        )

    async def list_mcps(self, user_id, q=None, cursor=None, limit=20):
        page = await fetch_our_catalog(query=q, after=cursor, limit=limit)
        return MCPHubPage(
            cards=[self._to_card(c) for c in page.items],
            next_cursor=page.next_cursor,
        )

    async def get_mcp(self, user_id: str, card_id: str) -> MCPCard:
        return self._to_card(await fetch_one(card_id))

自定义技能中心

from agentscope.app.hub import SkillArchive, SkillCard, SkillHubBase, SkillHubPage


class InternalSkillHub(SkillHubBase):
    def __init__(self) -> None:
        super().__init__(
            hub_id="internal",
            display_name="内部技能目录",
            description="由平台团队发布的技能。",
        )

    async def list_skills(self, user_id, q=None, cursor=None, limit=20):
        page = await fetch_our_catalog(query=q, after=cursor, limit=limit)
        return SkillHubPage(
            cards=[self._to_card(c) for c in page.items],
            next_cursor=page.next_cursor,
        )

    async def get_skill(self, user_id: str, card_id: str) -> SkillCard:
        detail = await fetch_one(card_id)
        return self._to_card(detail, markdown=detail.readme)

    async def download(self, user_id, card_id, version=None) -> SkillArchive:
        response = await self._client.get(f"/skills/{card_id}/archive")
        return SkillArchive(format="tar.gz", stream=response.aiter_bytes())

Hub 实例生命周期与进程同长，可以复用一个 HTTP 客户端：实现 __aenter__ / __aexit__，服务启动时进入、关闭时退出。

安全：可见性与访问控制

三个方法的第一个参数都是 user_id，不是摆设：

位置 规则
list_*只返回该用户可见的卡片
get_*对隐藏条目也抛 KeyError，否则猜 id 就能绕过
download技能包下载也要按 user_id 校验，理由同上
只在列表里过滤不算访问控制

调用方可以直接请求任意 card_id。可见性必须同时应用在 get_* 与 download 上。

另外：MCP 凭据加密保存、返回时脱敏；技能里的脚本仍受工作区权限与权限系统约束； 中心是第三方来源，接入前要评估可信度。

MCP 中心 vs 技能中心

维度 MCP 中心 技能中心
资源形态 一个可连接的服务 一个文件夹 + SKILL.md + 脚本
安装时填什么 凭证 / 配置（inputs_schema） 不填，只加入资源池
装配时做什么 创建 MCP 客户端，放进工作区 拉压缩包、解压到 skills 分区
运行位置 工作区后端（本地 / 沙箱） 工作区文件系统，由 Skill 查看器读取
更新 重装 / 轮换密钥 重新拉取最新压缩包

陷阱与窍门

把「安装」当「装配」

安装只进资源池，不会让智能体立刻拿到工具。还要在工作区里装配一次。

hub_id 重复

同一类型下 hub_id 必须唯一，否则服务启动直接报错。多目录用 github / internal 这种清晰前缀。

list_skills 里拉 SKILL.md

一页 20 条就是 20 次请求，很容易触发限流。列表只返回卡片元数据， 正文放在 get_skill。

只在 list_* 做可见性

get_* 与 download 都能被猜测 id 直接调用。 三处都要过滤，否则等于没有访问控制。

凭证字段没标 writeOnly

浏览器会拿到密钥。所有凭证字段都要 "writeOnly": true 与 "format": "password"。

技能包根目录没有 SKILL.md

解压后找不到技能定义，装配失败。压缩包要么是单个顶层文件夹，要么直接是文件， 但根目录必须有 SKILL.md。

装配技能时中心不可达

该技能会单独报错，同一请求中的其他技能照常装配。安装只存描述，不存文件副本， 所以每次装配都要能访问中心。
