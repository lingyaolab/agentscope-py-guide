04 · 模型接入

02、03 章里模型是个黑盒：给它消息，它产出内容块和事件。这一章打开这个黑盒，讲清三个对象—— Credential（凭证）、ChatModel（模型）、ModelCard（模型卡片）， 以及它们之间「谁绑定谁」的关系。

读完你能做到

  • 分清 Credential 与 ChatModel 的职责，知道换厂商时要改哪两行
  • 看懂 ChatModelBase.__call__ 的返回值、重试预算与取消行为
  • 用 list_models() 查到某家厂商当前可用的模型，而不是抄博客里的旧名字
  • 解释 FinishedReason 与 ReplyFinishedReason 为什么不是同一个枚举

先说为什么：凭证、模型、卡片是三件事

很多人把「接模型」理解成写一个 API key，然后在代码里写模型名。AgentScope 把这件事拆成了三层， 因为它们的变更频率完全不同：key 经常换、模型名偶尔换、调用协议很少换。

Credential（凭证）
「你是谁」：API key、base URL、组织 ID。它是一个 Pydantic 模型，可以存库、可以脱敏展示。
ChatModel（模型）
「怎么调用」：把 Msg 转成厂商格式、发 HTTP、解析流式响应、重试、统计 token。
ModelCard（模型卡片）
「有什么可选」：模型名、状态、上下文长度、输入输出类型、参数 schema。给前端下拉框和校验用。

还有一个不常被提到的第四层：Formatter。每个模型实现都自带一个 formatter， 负责把 Msg 的六种内容块翻译成厂商 API 要的结构（比如 DeepSeek 用 DeepSeekChatFormatter）。你通常不用碰它，但遇到「工具 schema 被厂商拒绝」时， 问题往往出在这一层。

凭证：一个 key 加一个 base URL

所有凭证都继承 CredentialBase _base.py:18。 基类只有两个通用字段：id（自动生成）和 name（展示名） _base.py:21。 真正区分厂商的是子类里的 type 字面量和各自字段。

厂商 type 关键字段
DeepSeek deepseek_credential_deepseek.py:22 api_key、base_url（默认 https://api.deepseek.com）
OpenAI / 兼容端点 openai_credential_openai.py:24 api_key、base_url（可选）、organization
Ollama ollama_credential_ollama.py:21 host（默认本地），没有 key
DashScope dashscope_credential api_key

api_key 的类型是 SecretStr，打印时会显示成掩码，避免日志里泄露。 但这只是第一道防线：不要把凭证对象直接 model_dump() 后写日志或提交到仓库， 真实项目里应该放环境变量或密钥管理服务。

凭证还负责「绑定模型类」

每个凭证类都要实现 get_chat_model_class() _base.py:32， 告诉框架「我这种凭证该配哪个模型实现」。DeepSeek 的实现返回 DeepSeekChatModel _deepseek.py:37。

这也是 CredentialBase.list_models() _base.py:118 能工作的原因：它先找到绑定的模型类，再让模型类列出自己的卡片。

CredentialFactory：从字典还原凭证

凭证要存库、要在服务层从数据库读出来，就必须能序列化和反序列化。 CredentialFactory _factory.py:20 用一个以 type 为判别字段的联合类型完成这件事： 

from agentscope.credential import CredentialFactory

data = {
    "type": "deepseek_credential",
    "name": "我的 DeepSeek",
    "api_key": "sk-...",
}
cred = CredentialFactory.from_dict(data)   # → DeepSeekCredential

三个常用方法：

方法 用途
from_dict(data)_factory.py:78 按 type 反序列化成具体凭证
register_credential(cls)_factory.py:63 注册自定义厂商；type 必须唯一
list_schemas()_factory.py:115 给前端动态渲染凭证表单
自定义厂商最少要写两个类

一个 XxxCredential（带唯一 type、实现 get_chat_model_class） 和一个 XxxChatModel（实现 _call_api）。注册后用 CredentialFactory.from_dict 就能识别。

ChatModel：一个 __call__，两种返回

ChatModelBase _base.py:37 把所有厂商的共同点收敛成一个可调用对象： 

res = await model(
    messages,                 # list[Msg]
    tools=None,               # list[dict] | None
    tool_choice=None,         # ToolChoice | None
    **kwargs,
)

# stream=False → ChatResponse
# stream=True  → AsyncGenerator[ChatResponse, None]

签名在 _base.py:184。 它负责三件模型实现不该重复写的事：

  1. 重试：最多 max_retries + 1 次，只有 _get_retryable_exceptions() 里列的异常才计入 _base.py:210。
  2. 取消：遇到 asyncio.CancelledError 时，返回一个 finished_reason=interrupted 的 ChatResponse，而不是把异常抛给上层 _base.py:221。
  3. 流式收口：把厂商的碎片聚合成一个 is_last=True 的完整响应， 作为流的最后一项 _utils.py:274。

真正和厂商打交道的是抽象方法 _call_api() _base.py:303。 DeepSeek 的实现里能清楚看到「参数怎么拼、流式怎么解析」 _model.py:157。

两个容易忽略的辅助方法

  • count_tokens(messages, tools) _base.py:379： 默认用「字节数 / 4」粗估，不调用 tokenizer。够用来做上下文预算，不要拿它做计费。
  • generate_structured_output(...) _base.py:467： 结构化输出的底层入口，通常由 Agent 调用，不需要你手动调。

直接调用模型的完整例子

import asyncio
import os

from agentscope.credential import DeepSeekCredential
from agentscope.message import SystemMsg, UserMsg
from agentscope.model import DeepSeekChatModel


async def main() -> None:
    model = DeepSeekChatModel(
        credential=DeepSeekCredential(
            api_key=os.environ["DEEPSEEK_API_KEY"],
        ),
        model="deepseek-v4-flash",
        stream=False,
    )

    res = await model(
        [
            SystemMsg(name="system", content="回答尽量短。"),
            UserMsg(name="user", content="用一句话解释什么是 token。"),
        ],
    )

    print([b.text for b in res.content if b.type == "text"])
    print(res.usage)


asyncio.run(main())

参数与默认值：stream / retries / context_size

基类构造函数的默认值 _base.py:62：

参数 基类默认 含义
stream True_base.py:67 底层是否走流式
max_retries 3_base.py:68 重试次数，总尝试 = 4 次
retry_delay 1.0 每次重试前固定等待秒数，不是指数退避
context_size 32768_base.py:70 上下文压缩的预算基准，不是模型硬上限

不同厂商会覆盖 context_size：

模型类 context_size 默认 出处
DeepSeekChatModel 65536 _model.py:87
OpenAIChatModel 128000 _model.py:122
OllamaChatModel 32768 _model.py:64

DeepSeek 的生成参数

DeepSeekChatModel.Parameters _model.py:29 里全是可选字段，默认 None：

字段 默认 说明
max_tokens None_model.py:32 不传则由服务端决定
thinking_enable False_model.py:39 开启思考模式
reasoning_effort None high / max
temperature None_model.py:60 范围 0–2；None 表示不发送
top_p None_model.py:68 范围 0–1；None 表示不发送
None 不等于 0

temperature=None 的语义是「这个字段不传给厂商」，由厂商用默认温度； 它和 temperature=0（确定性输出）是两件事。想要固定输出，显式传 0。

ChatResponse 与 token 用量

ChatResponse _model_response.py:32 是模型层的统一返回：

字段 类型 说明
content list[TextBlock | ToolCallBlock | ThinkingBlock | DataBlock] 本段内容；流式时是增量
is_last bool 是否是最后一段；最后一段通常是完整响应
usage ChatUsage | None token 用量
finished_reason FinishedReason 只有 completed / interrupted
id / created_at / metadata — 追踪与扩展

ChatUsage _model_usage.py:10 记录四类 token 与耗时： input_tokens、output_tokens、time（秒）、 cache_input_tokens、cache_creation_input_tokens。 成本核算要连缓存 token 一起算，不能只乘输入输出。

两个 FinishedReason 不是同一个枚举

模型层的 agentscope.model.FinishedReason 只有 completed / interrupted _model_response.py:21； Agent 回复层的 agentscope.types.ReplyFinishedReason 还有 exceed_max_iters / error。看到同名别混用。

错误与重试：哪些会重试，哪些立刻抛

重试策略是「白名单」：只有 _get_retryable_exceptions() 返回的异常才重试， 其余立刻抛出 _base.py:228。 DeepSeek 的白名单是四类：

异常 典型场景 是否重试
APIConnectionError 网络断、DNS 失败 是
APITimeoutError 请求超时 是
RateLimitError 429 限流 是
InternalServerError 厂商 5xx 是
AuthenticationError 401 key 错 否，直接抛
BadRequestError 参数不合法、schema 被拒 否，直接抛

白名单定义在 _model.py:138。 重试等待是固定 retry_delay，没有指数退避也没有 jitter _base.py:241。 默认 3 次重试 + 1 秒间隔，最坏情况多等 3 秒。

模型级重试 ≠ Agent 级降级

这里的 max_retries 只管同一个模型的传输重试。想要「主模型挂了换备用模型」， 用 Agent 的 ModelConfig(fallback_model=...)，那是另一层策略。

模型卡片：从 YAML 到前端下拉框

ModelCard _model_card.py:11 是一个纯描述对象，关键字段：

字段 作用
name / label API 里的模型名 / 界面展示名
status active / deprecated / sunset_model_card.py:30
input_types / output_types 支持文本、图片、思考等哪些类型
context_size / output_size 上下文与最大输出 token
parameter_schema 由模型的 Parameters 类生成的 JSON Schema
parameters_overrides 按模型覆盖的取值范围

卡片不是手写在代码里的，而是每个模型实现旁边有一个 _models/ 目录， 里面放 YAML。list_models() _base.py:135 会扫描这些 YAML，合并参数 schema 后返回 list[ModelCard]。 

from agentscope.credential import DeepSeekCredential

for card in DeepSeekCredential.list_models():
    print(card.name, card.status, card.context_size, card.output_size)

厂商对照：DeepSeek / OpenAI 兼容 / Ollama / DashScope

所有厂商都是「换一对类」：凭证类决定连哪儿，模型类决定怎么调。

厂商 凭证 模型类 接入要点
DeepSeek DeepSeekCredential DeepSeekChatModel base URL 固定，通常只需 key
OpenAI / 兼容 OpenAICredential OpenAIChatModel 设 base_url 即可接自建网关或其他兼容服务
Ollama OllamaCredential OllamaChatModel 本地 ollama pull 后填模型名；无 key
DashScope DashScopeCredential DashScopeChatModel 通义千问系列

陷阱与窍门

按博客里的旧模型名下注

模型名会 sunset。用 list_models() 看 status， 不要假设「deepseek-chat」永远可用。本站已经因此把 01、02 章统一到 deepseek-v4-flash。

流式遍历时把最后一段也打印出来

流的最后一项是 is_last=True 的聚合响应，内容是完整文本。 如果你既不跳过它、又逐字打印前面的 delta，最后会把整段答案重复输出一遍。

把 max_retries 当成「总尝试次数」

实际总尝试是 max_retries + 1。默认 3 表示「失败后再试 3 次」， 一共 4 次请求、最多等待 3 秒。

context_size 不是模型的硬上限

它只是上下文压缩中间件的预算基准。DeepSeek 这里默认 65536，而模型卡片写的 1,000,000 是真实窗口；两者不是一回事，别拿 context_size 去判断「能塞多少」。

Ollama 的模型必须先拉到本地

OllamaChatModel(model="qwen2.5:7b") 只是告诉框架用哪个名字； 本地没 ollama pull qwen2.5:7b 时会在第一次调用报 404。
